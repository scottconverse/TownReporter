# Security policy

TownReporter is a self-hosted civic newsroom. Anyone can clone it and run it on
the public internet, which means a vulnerability here is a vulnerability in
every paper someone else is running. Coordinated disclosure matters more than
usual for this project.

## Supported versions

| Version | Supported |
|---|---|
| 0.5.x | Yes — fixes land on the current release |
| < 0.5 | No. Upgrade; the 0.5.0 release closed an SSRF re-resolution gap and a duplicate-job defect. |

There is one active release line. If you are running an older tag, the honest
advice is to update before reporting, in case the issue is already closed.

## Reporting a vulnerability

**Do not open a public GitHub issue.** A public issue tells every operator
running a clone at the same moment it tells the maintainer.

Report privately to **`<fill in>`**. Please include:

- What the issue is, in one or two sentences.
- The version or commit you tested.
- How you reached it: the route, the request, or the steps on the desk.
- What an attacker gets — read access, write access, another user's newsroom,
  the host, someone's model credentials.
- A proof of concept if you have one. A curl command is ideal.

What to expect:

| | |
|---|---|
| Acknowledgement | within 3 working days |
| First assessment | within 7 days |
| Fix or a stated plan | within 30 days for anything reachable from an unauthenticated request |

This is a project maintained by one person. If you do not hear back inside the
acknowledgement window, send the mail again before assuming it was ignored.

Credit is offered in the changelog entry for the fix unless you would rather
not be named. There is no bug bounty.

## Scope

**In scope** — the code in this repository:

- Authentication and session handling (`better-auth`, the `__Host-` cookie, the
  bearer path for partitioned-cookie previews).
- The desk boundary: every desk action runs through `deskMiddleware`, which
  asserts same-site, resolves the user from the session rather than from
  anything the client sends, and requires owner or editor membership of the
  newsroom. A way around any of those three is a report.
- Newsroom ownership: `NEWSROOM_SETUP_TOKEN` gating, and the first-account-owns
  behaviour when it is unset.
- The SSRF guard on outbound fetches. The address that is approved must be the
  address that is connected to; a way to make those differ, or to reach a
  private range, loopback, link-local or a mapped IPv6 loopback, is a report.
- The cron endpoint (`/api/cron/monitors`) and `CRON_SECRET` handling.
- The Opinion voice-file boundary: the path is validated and only the path
  reaches a command line. Anything that gets file contents onto a command line,
  or accepts a relative path or a path inside the repository, is a report.
- Injection of any kind into the public paper — a published story, the feed,
  the sitemap, or the evidence routes.
- Anything that puts a third-party asset onto a reader's page.

**Not in scope** — configuration choices the operator makes and the docs warn
about:

- Running with `VITE_AUTH_ENABLED=false` on a public host. Every document that
  mentions this flag says not to do it.
- Running on the public internet with no `NEWSROOM_SETUP_TOKEN`, so the first
  stranger to sign up owns the desk.
- PGLite data loss on restart. Documented behaviour, not a defect.
- Vulnerabilities in the model provider you chose, in a gateway you run, or in
  the civic websites the app fetches.
- Anything requiring an attacker who already has shell on the machine running
  the newsroom. That machine holds the operator's own model login.
- Reports generated by a scanner with no demonstrated path to impact.

## What already exists

Context, so you can aim at what is not yet covered:

- Outbound fetches are guarded at connect time, after a 0.5.0 fix in which DNS
  was resolved and then allowed to resolve again.
- Mapped IPv6 loopback (`http://[::ffff:7f00:1]/`) is blocked.
- The default test suite is offline by construction, and a test enforces that
  no test can reach a live model unasked.
- The reader's page carries no third-party asset; the Server page re-checks it.
- CI boots both the dev server and a real production build and exercises them
  in a browser.

## If you operate a TownReporter

You are the publisher and you are also the sysadmin. The three settings that
matter most are `NEWSROOM_SETUP_TOKEN` (set it on any public host),
`BETTER_AUTH_SECRET` (a long random string, never a default), and `HOST` (bind
loopback when a tunnel or proxy fronts the app). `docs/setup.md` explains all
three, and `docs/setup.md` §"What leaves this machine" lists what your desk
sends where.
