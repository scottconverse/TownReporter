## Current release work — 2026-09-26

The current software version is [0.6.71](docs/releases/0.6.71.md): the local model picker says what is loaded, and the desk will not ask a server for a model that is not. Choosing **Local model** listed every model on disk with nothing to say which were in memory — discovery has always read LM Studio's `/api/v0/models` and Ollama's `/api/ps`, so the load state was known and simply never reached the list. A model in memory now reads `<id> · loaded`, its id still first because that is the part an editor is choosing between, and inside each server group the loaded models sort ahead of the rest, by id within each group. **Use whatever is loaded** is the first choice and the new default when a local server reports a loaded non-embedding model and nothing has been stored; when nothing is loaded the default is unchanged and the help line says which model it is using and why. It is stored as an ordinary pick with a sentinel (`*` in both halves) rather than a new column — `base_url` and `model_id` are plain `text not null` with no value constraint, the save validator accepts any two non-empty strings, and a real pick always carries a server address, so the sentinel cannot collide with one — which is why it needs **no migration**. At call time it resolves through the same function the Automatic rung already used, LM Studio before Ollama and in that order, and the receipt names the model that actually ran (`Local model (halo-brain-35b)`), as the rung does. **The desk never loads a model**: a hand-picked, non-cloud model on a server that reports load state, when that report says not loaded, stops before the call with *"`<id>` is not loaded in LM Studio. Load it there, or pick Use whatever is loaded."*, and **Use whatever is loaded** with nothing loaded stops with *"Local model: nothing is loaded in LM Studio or Ollama. Load a model there, or pick a model."* — each the desk's own complete sentence, reaching the operator as the guidance line. A server that reports **no** load state (llama.cpp) behaves exactly as before, an Ollama Cloud pick is never blocked, and the help line under the select now answers the question in words for each of its states: loaded now, not loaded, no load state reported, a cloud model, which model **Use whatever is loaded** is pointing at, or which model a run would fall back to. The release guide keeps source, package, GitHub publication, and production deployment as separate facts.

This change adds no migration and no scheduled task, service or program. **Use whatever is loaded** is an ordinary row in the model-choice table the picker already writes — `base_url` and `model_id`, plain text with no value constraint — so nothing in the database changes shape: no column, table or index is added, and everything a newsroom has already stored still reads as it did.

The previous release was [0.6.70](docs/releases/0.6.70.md): corrections that can fix the words, YouTube read through Google's own service, a screen that can clear the suggested sources, and a style check on a news draft. **The correction box no longer starts empty.** Opening a correction shows **What was wrong** and **What is right**, and **Suggest wording** asks the story model, through the same Automatic provider ladder every other call site uses, for one note in the paper's voice built only from those two lines and the story it can see and forbidden to add a fact of its own — read back with the same care as a headline suggestion, so a fenced block, a "Correction:" label, quotes, a lead-in sentence or anything past the first line comes off, and a list of options, a fragment or a paragraph longer than the schema allows is refused rather than offered. **Use a plain note** writes *An earlier version of this story said … In fact, …* on the desk with no model and no network call, and the note goes into the box, never onto the paper, until the editor presses **Publish correction**. **Also fix the story text** is a second checkbox, off unless the editor turns it on, that opens the printed body in an editor already holding the story as it printed; one press of **Publish correction** then publishes the note, updates the body and writes the old body to the append-only `article_body_history` in **one transaction**, the slug never moves, and a fix that is unchanged (including whitespace-only) or blank is refused with neither half written. **YouTube** is read through the YouTube Data API v3 when a key is saved on the Server page — encrypted with the same helper the custom AI connections use, write-only, sent in the `x-goog-api-key` header and never in a URL, a reply, a log line or an error — in at most three 1-unit calls (`channels.list`, `playlistItems.list`, `videos.list`) and never `search.list`; the channel tab HTML, the public feed and the yt-dlp listing stay as the fallback for no key, a refused key, a dead network, an unreadable reply or a day whose 10,000 units are already spent, a quota refusal is terminal for the Pacific day, and every receipt says which path ran. **Sources** gains **Suggested sources: N** — newest first, each row carrying the model's one sentence about the page and the suggester it came from — with **Anyone / The scan / The research pass / The Dark Desk / Not recorded** filters, per-row accept, reject and note, and batch accept/reject that commits as one transaction, with the section half still owner-only. **Style check** measures a news draft in code — unnamed attribution, importance-only sentences, participle tails, dressed-up verbs, filler words, synonym cycling, paste artifacts, tracking parameters and URL redirects, paragraphs over the form's cap, sentence-length variation and six-word repeats — and asks the model to repair only what the code found, at most two rounds, refusing a repair that flattens the sentence rhythm or changes any quotation, number, name or URL; the findings are stored with the draft and a draft that still has `fix` findings gains the review reason `style-audit-open`. That release added three additive migrations (`0095_article_body_history.sql`, `0096_youtube_data_api.sql` and `0097_suggested_source_origin.sql`) and no scheduled task.

The release before that was [0.6.69](docs/releases/0.6.69.md): the news lane's lead matching and the machine upkeep. Until this release a story the scanner met twice in one run was filed twice, and a finding that matched a lead the editor had killed was dropped without a word even when it carried facts the killed lead never had. Every one of those cases is now decided before anything is written: two findings in the same run that are the same story become one lead with both source addresses kept; a strong match against a live lead still becomes **Possible duplicate** in Held; and a strong match against a killed lead is filed as **Developing: new facts on a story you killed** — with the old kill reason and a link to the killed lead beside it — only when the new finding brings a concrete date, dollar amount or number the killed lead lacked, while a killed lead whose facts have not changed is folded into the old one and the scan says so. An index, section or RSS feed address no longer counts as the same address as an article. The Queue's NEW row states **Looks already printed: \<headline\>** in place of the bare **≈ PRINTED** chip and offers a one-press **Kill as duplicate**; the Held tab carries a count badge; and **Compare** shows the two leads side by side with three presses — **Not a duplicate — move to New**, **Same story — kill this one**, **Newer facts — reopen the old one**. A killed lead's own page shows the lead, when and why it was killed, and a **Reopen** that keeps the record and records that the kill was undone. Machine upkeep in the same release: `ops/promote.ps1` and `installer/Install.ps1` hash files through `Get-TownReporterFileHash` rather than `Get-FileHash`, hand-named safety copies are carried to the second drive too, `ops/start-stage.ps1` starts the port-3100 test copy without touching the live paper, and the writing ladder's middle rung uses whichever model LM Studio has loaded, with `TOWNREPORTER_QWEN_MODEL` pinning one. That release added one additive migration (`0094_lead_kill_record.sql`) and no scheduled task.

The following acceptance work remains EXPLICITLY OPEN and is not closed by this release: fresh-machine human acceptance of the Windows install; the live provider matrix (configured-provider behaviour across the full provider set); five useful Dark Desk outcomes plus the September 3–8 replay; and the post-crash detached-child limitation. Production deployment and live-model proof are not asserted here. Nothing in this release was run against a real AI model, and no screenshot here was taken against the live paper.
