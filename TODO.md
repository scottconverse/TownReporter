## Current release work — 2026-09-26

The current software version is [0.6.68](docs/releases/0.6.68.md): the backups and the alerts. Until this release a backup existed only as a side effect of a promotion — `ops\promote.ps1` was the only file in the tree that ran `pg_dump`, no scheduled task ran one, and the folder beside the app held 61 files and about 12.5 GB with nothing pruned and nothing on the second drive. `ops\lib-backup.ps1` now holds that one dump call and three callers use it: the nightly run driven by the five-minute watchdog the owner already has (after 2:00 AM local, when the newest backup is older than 20 hours, skipped while an editor job is running, never two at once), `ops\backup.ps1` — also the Control page's **Back up now** button — and `promote.ps1` itself. Every local backup not already verified on D: is copied, each copy written as `.partial` and renamed onto its real name only when its size **and** SHA-256 match, and the local folder is pruned to the newest three **only after** every local file is proved to be on D:. A missing or unwritable drive, a copy that fails its check, or a local file that is not a complete dump each delete nothing, say which file and why, and raise an alert; nothing is deleted from D: by any path, and a copy that would leave under 100 GB free is refused. A file counts as a backup only if it opened, closed, ended with the closing marker its opening marker promised, and passed a size floor. `ops\lib-alert.ps1` watches six conditions — the desk down over 10 minutes, the public site down over 10 minutes, the daily scan failed or not run by 8:00 AM when scheduled, the last good backup over 30 hours old, the offsite copy failing, the second drive short of room — firing once when each starts and once when it clears, into the Control page's new **Attention** card, a Windows notification, and a phone push through ntfy that is off until `ALERT_NTFY_TOPIC` is set in `.env`. The page also gains **Last backup** and **Copy on D:**, both read from the reports the runs write rather than by enumerating a drive that may have gone to sleep, and no card is green when its probe did not answer. The watchdog now reads `LastTaskResult` `267009` (`SCHED_S_TASK_RUNNING`) as a task still running rather than as a failure. The release guide keeps source, package, GitHub publication, and production deployment as separate facts.

This change adds no migration and no scheduled task, service or program: the nightly backup and the alerts ride on the five-minute watchdog that already exists, and `ops\backup.ps1` is a script, not a task. The one-time copy of the backups an existing installation already has is a person running `ops\backup.ps1 -Offsite` once; it is not automated here, and the coordinator runs it after this release is deployed.

The previous release was [0.6.67](docs/releases/0.6.67.md): the editor's controls. A to-do the desk wrote itself, longer than the bound the desk read to-dos back at, used to refuse a save with raw validation output; the desk now clips what it writes at a word boundary, reads to-dos at that same bound, and normalises a stored one rather than refusing the round trip, and a failure in the editor's notes no longer blocks the printing of a valid draft. A headline an editor changed survives a **Redraft** and can be rewritten after the story has printed, from the story page and from **Published**, keeping the slug and every link, with the old headline, the account and the time in the append-only `article_headline_history` table; **Use the lead's headline** and **Suggest headlines** sit beside the box, and nothing is applied without a click. Publish reads **Publish in \<Section\>**, confirms that section for the version being printed in the same press, is disabled with the reason beside it when the scanner placed no section, and logs and counts on Stats every story whose section differed from the model's. That release added one additive migration (`0093_editor_headline_control.sql`) and no scheduled task.

The release before that was [0.6.66](docs/releases/0.6.66.md): the paper comes back by itself after a reboot. The logon start waits for Postgres to answer a real query rather than trusting an open TCP port, runs migrations through `cmd.exe` so a child's stderr can never terminate the script, retries them three times with every attempt in `logs/townreporter.log`, and exits non-zero when the schema is still not current instead of appearing to have served the paper. The watchdog reads that task result and, after a three-minute boot grace, runs the `\TownReporter` task itself when the paper is down and that task last failed — never a second copy of the start, and never inside the grace. The Redlib install root is now `REDLIB_INSTALL_ROOT` in the app's `.env` (environment variable wins), outside AppData, with `ops/redlib-relocate.ps1 -To <dir>` to move an existing MSIX-redirected install out in one step. It added no migration and no scheduled task.

The following acceptance work remains EXPLICITLY OPEN and is not closed by this release: fresh-machine human acceptance of the Windows install; the live provider matrix (configured-provider behaviour across the full provider set); five useful Dark Desk outcomes plus the September 3–8 replay; and the post-crash detached-child limitation. Production deployment and live-model proof are not asserted here. Nothing in this release was run against a real AI model, and no screenshot here was taken against the live paper.

Meeting capture specifically does not yet include: a provisional-to-revision cycle observed against a real capture (the re-check runs, but nothing inserts a link row, so it finds nothing to look at), and any path from a transcript to a story. Section 5 produces chunks, alignments and structured votes and deliberately does not draft.
