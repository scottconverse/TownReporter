## Current release work — 2026-09-27

The current software version is [0.6.75](docs/releases/0.6.75.md): a small hotfix for the Queue's batch panel. Under "Draft selected", the panel loaded the newsroom's latest batch and drew every job in it forever, including stories the paper had already printed or that an editor had killed, each still carrying a **Redraft** button. **Published and killed stories now drop out of the panel**, and it draws nothing at all once that leaves the batch empty — a batch that is still running is shown exactly as before. `getDraftBatch` left-joins the lead into the same read that already loads the batch's jobs, so every item carries the story's current status with no extra round trip; the filter names the two states it drops (published, killed) rather than allow-listing the rest, so a lead that was simply deleted still shows. **A finished batch gets a Dismiss button**: one nullable timestamp on the batch row, set once and never cleared, so the next batch an editor starts is a new row and shows normally. **One additive migration**, `0104_draft_batch_dismissed.sql`, adds the nullable `dismissed_at timestamptz` column and runs on start. **A new CI job, `batch-published-panel-e2e`**, drives the owner's own path — one desk, one Custom AI connection, two leads, one batch, one of the two stories printed — against a fake OpenAI-compatible provider and a fresh, DATABASE_URL-free database, and fails against 0.6.74 exactly where the owner did. The release before this one was [0.6.74](docs/releases/0.6.74.md): the desk's five main screens restyled to the redesign drawings, three fixes for a bad night on 2026-09-26, and readable, actionable claim sources on the Reporting tab. **Opinion**, **Sources & scan**, **Published**, **Server & newsroom** and **Dark Desk** keep every action they had; what changed is the layout on top of it, following `docs/design/handoff-2026-09-26/design/Desk Screens.dc.html` — the same panels, row shapes, filter chips and button family the rest of the desk already uses. No migration, no new color, no new route, no action removed. **The paper no longer waits behind a nightly backup**: nearly every page's first database call ran `alter table ... add column if not exists` — the strongest lock there is — against a table `pg_dump` held a read lock on for the length of the dump, so the ALTER queued behind the dump and every other read queued behind the ALTER. Sixteen modules now go through one caching helper, `ensureSchemaOnce` (`src/lib/db.ts`), that records a batch has already run and skips it after the first call in a process; no statement's text or order changed. **The watchdog knows its own server**: it used to compare a forward-slash path against a Windows command line reported with backslashes, a comparison that could never match, so it logged "not this app" instead of restarting a stalled server; it now asks the same slash-normalizing predicate the rest of the ops scripts use. **A backup that fails cleans up after itself**: instead of keeping the newest two half-written `.incomplete` dumps unread, the backup library now logs the file's size and its last 2 KB as text, then deletes it, and sweeps any leftover `*.sql.incomplete` from the folder a dump was just attempted in. **Every sourced claim on the Reporting tab gets a readable link, Pull and Add to notes**: the short site name is the link text, with the full address on hover; **Pull** reads that exact source page through the existing ingest guard, no new model call; **Add to notes** writes `<claim> — <url>` as one reporting-note line, once; and a new CI job, `claim-sources-pull-0674`, proves the path end to end against a fake provider. **Redraft now reads the editor's own reporting notes** for an ordinary, non-meeting story, labeled as leads to verify rather than evidence. **No migration**: `git diff 5629cc79..HEAD --stat -- migrations` shows nothing under `migrations/` changed since 0.6.73. The release before that was [0.6.73](docs/releases/0.6.73.md): the AI follow-up agents, the editor's dialogs, the Stats screen and the paper's one-line section nav, plus two additive migrations. **A follow-up can now be an agent, not just an ask.** **+ New AI follow-up** names a question and a method — **Re-check pages**, on the page-watch engine the desk already had (the same capture, the same OCR, the same "unchanged / changed / refused" vocabulary, not a second crawler), **Search public records**, through the desk's own web search with a model reading the hits to decide whether any actually answers the question, or **Watch for next agenda**, on a meeting body's PrimeGov portal, which is what the daily scan's meeting capture already reads — and the desk then works it on a schedule and reports what it finds. **"Nothing changed" and "could not check" are different cards**: an agent that arrived and found the page unchanged is **healthy** ("Checked · no change"), while one that could not read the page carries the real reason ("The page timed out.", "This build can only watch PrimeGov portals.") and a **Retry now** button, because a follow-up quietly failing for a week must not look like one quietly working. Each card belongs to one of four filters — **Active**, **Found something**, **Could not check**, **Stopped** — and shows the method line, the question in the editor's own words, the latest result, the linked story and the next check. **A finding writes one line into that story's reporting notes through the same column and helpers the notes panel uses, and it never publishes** — nothing in the feature writes an article, a draft or a lead, and there is no publish path out of it at all. **The nine dialogs the redesign draws for the editor are built, and no screen mounts them yet**, which this release says plainly: **New story** in its three tabs, **Add a lead**, **Add sources to watch** with a preview table showing what will be added before it adds it, **Add to this story** where the first press writes nothing and the second saves exactly the bytes the editor read, **Start a Dark Desk file**, **Hold this lead**, **Headline**, the **More ▾** lead-row menu, and the **kill pattern** under a source, which always prints both numbers because a source with nine kills and none of them its fault is a source to keep. Six server functions stand behind them — `addLead`, `holdLead`, `sourceKillPattern`, `findSources`, `weaveIntoStory`, `chooseHeadline` — tested with a fake database and a **counting** model, which is how "the model is not asked again on the confirm press" is asserted rather than described, and `weaveIntoStory`'s mode is **required** so a request that forgot to say "paste in as-is" cannot default into a model call; the hold reason rides in the lead's existing notes rather than a new column, so **no migration**. **Stats** (`/desk/stats`) counts readers without naming one: a range control with Export CSV, the live panel, the summary cells, the thirty-day chart, the story read-through table, the three bar panels, the hour-by-day heatmap and the trust signals, with **Section chosen by hand** and **Saved reports** untouched. **"Reading right now"** is computed in memory on the server over a rolling thirty-minute window and never written with any key that could name a reader, so it empties on a restart and is one process wide. **Visits** counts page loads whose referrer is not this paper's own host, an empty referrer counts as outside and the page says so, our own story paths are **Read another story** rather than a visit, and **Left without reading** is a load under ten seconds of active reading. **There is no daily unique count anywhere**, because computing one would require exactly the identifier the rule forbids; **returning readers** is not measured; and the location panel prints that **the paper does not look up where readers are** and offers nothing else — there is no GeoIP database, and the IP is not read for any purpose. **The paper's 21 section links stay on one line at every width**, cut by measuring the links just rendered rather than by a fixed count, with what does not fit behind a keyboard-reachable 44px **More sections** disclosure and the mobile path unchanged, and the article page's links now sit on the masthead row beside the wordmark. **Dark mode** joins Search, Saved and Editor's desk in the top bar as a one-press switch — and that button fixed the reason the toggle never repainted the **article** page, because `refreshReader()` re-renders the appearance provider, which is the button's own ancestor, so a write queued inside the state updater had not happened before the provider re-read the stored value. The two migrations are additive and run on start; there is no new scheduled task, service, program, port or installer step. No model was called or loaded to build or check this release — the checks ran against fakes and PGlite. The release before that was [0.6.72](docs/releases/0.6.72.md): the redesign reaching the paper and the desk at once — the re-laid-out front page and article, the geography pills that finally filter, the job-progress card and the Models screen, plus three additive migrations. The release before that was [0.6.70](docs/releases/0.6.70.md): corrections that can fix the words, YouTube read through Google's own service, a screen that can clear the suggested sources, and a style check on a news draft. **The correction box no longer starts empty.** Opening a correction shows **What was wrong** and **What is right**, and **Suggest wording** asks the story model, through the same Automatic provider ladder every other call site uses, for one note in the paper's voice built only from those two lines and the story it can see and forbidden to add a fact of its own — read back with the same care as a headline suggestion, so a fenced block, a "Correction:" label, quotes, a lead-in sentence or anything past the first line comes off, and a list of options, a fragment or a paragraph longer than the schema allows is refused rather than offered. **Use a plain note** writes *An earlier version of this story said … In fact, …* on the desk with no model and no network call, and the note goes into the box, never onto the paper, until the editor presses **Publish correction**. **Also fix the story text** is a second checkbox, off unless the editor turns it on, that opens the printed body in an editor already holding the story as it printed; one press of **Publish correction** then publishes the note, updates the body and writes the old body to the append-only `article_body_history` in **one transaction**, the slug never moves, and a fix that is unchanged (including whitespace-only) or blank is refused with neither half written. **YouTube** is read through the YouTube Data API v3 when a key is saved on the Server page — encrypted with the same helper the custom AI connections use, write-only, sent in the `x-goog-api-key` header and never in a URL, a reply, a log line or an error — in at most three 1-unit calls (`channels.list`, `playlistItems.list`, `videos.list`) and never `search.list`; the channel tab HTML, the public feed and the yt-dlp listing stay as the fallback for no key, a refused key, a dead network, an unreadable reply or a day whose 10,000 units are already spent, a quota refusal is terminal for the Pacific day, and every receipt says which path ran. **Sources** gains **Suggested sources: N** — newest first, each row carrying the model's one sentence about the page and the suggester it came from — with **Anyone / The scan / The research pass / The Dark Desk / Not recorded** filters, per-row accept, reject and note, and batch accept/reject that commits as one transaction, with the section half still owner-only. **Style check** measures a news draft in code — unnamed attribution, importance-only sentences, participle tails, dressed-up verbs, filler words, synonym cycling, paste artifacts, tracking parameters and URL redirects, paragraphs over the form's cap, sentence-length variation and six-word repeats — and asks the model to repair only what the code found, at most two rounds, refusing a repair that flattens the sentence rhythm or changes any quotation, number, name or URL; the findings are stored with the draft and a draft that still has `fix` findings gains the review reason `style-audit-open`. That release added three additive migrations (`0095_article_body_history.sql`, `0096_youtube_data_api.sql` and `0097_suggested_source_origin.sql`) and no scheduled task.

The release before that was [0.6.69](docs/releases/0.6.69.md): the news lane's lead matching and the machine upkeep. Until this release a story the scanner met twice in one run was filed twice, and a finding that matched a lead the editor had killed was dropped without a word even when it carried facts the killed lead never had. Every one of those cases is now decided before anything is written: two findings in the same run that are the same story become one lead with both source addresses kept; a strong match against a live lead still becomes **Possible duplicate** in Held; and a strong match against a killed lead is filed as **Developing: new facts on a story you killed** — with the old kill reason and a link to the killed lead beside it — only when the new finding brings a concrete date, dollar amount or number the killed lead lacked, while a killed lead whose facts have not changed is folded into the old one and the scan says so. An index, section or RSS feed address no longer counts as the same address as an article. The Queue's NEW row states **Looks already printed: \<headline\>** in place of the bare **≈ PRINTED** chip and offers a one-press **Kill as duplicate**; the Held tab carries a count badge; and **Compare** shows the two leads side by side with three presses — **Not a duplicate — move to New**, **Same story — kill this one**, **Newer facts — reopen the old one**. A killed lead's own page shows the lead, when and why it was killed, and a **Reopen** that keeps the record and records that the kill was undone. Machine upkeep in the same release: `ops/promote.ps1` and `installer/Install.ps1` hash files through `Get-TownReporterFileHash` rather than `Get-FileHash`, hand-named safety copies are carried to the second drive too, `ops/start-stage.ps1` starts the port-3100 test copy without touching the live paper, and the writing ladder's middle rung uses whichever model LM Studio has loaded, with `TOWNREPORTER_QWEN_MODEL` pinning one. That release added one additive migration (`0094_lead_kill_record.sql`) and no scheduled task.
