## Current release work — 2026-09-25

The current software version is [0.6.67](docs/releases/0.6.67.md): the editor's controls. A to-do the desk wrote itself, longer than the bound the desk read to-dos back at, used to refuse a save with raw validation output; the desk now clips what it writes at a word boundary, reads to-dos at that same bound, and normalises a stored one rather than refusing the round trip, and a failure in the editor's notes no longer blocks the printing of a valid draft. A headline an editor changed survives a **Redraft** and can be rewritten after the story has printed, from the story page and from **Published**, keeping the slug and every link, with the old headline, the account and the time in a new append-only `article_headline_history` table; **Use the lead's headline** and **Suggest headlines** sit beside the box, and nothing is applied without a click. Publish now reads **Publish in \<Section\>**, confirms that section for the version being printed in the same press, is disabled with the reason beside it when the scanner placed no section, and logs and counts on Stats every story whose section differed from the model's. The release guide keeps source, package, GitHub publication, and production deployment as separate facts.

This change adds one additive migration (`0093_editor_headline_control.sql`) and no scheduled task: the new columns and the history table only add, and the existing logon task and five-minute watchdog are unchanged.

The previous release was [0.6.66](docs/releases/0.6.66.md): the paper comes back by itself after a reboot. The logon start waits for Postgres to answer a real query rather than trusting an open TCP port, runs migrations through `cmd.exe` so a child's stderr can never terminate the script, retries them three times with every attempt in `logs/townreporter.log`, and exits non-zero when the schema is still not current instead of appearing to have served the paper. The watchdog reads that task result and, after a three-minute boot grace, runs the `\TownReporter` task itself when the paper is down and that task last failed — never a second copy of the start, and never inside the grace. The Redlib install root is now `REDLIB_INSTALL_ROOT` in the app's `.env` (environment variable wins), outside AppData, with `ops/redlib-relocate.ps1 -To <dir>` to move an existing MSIX-redirected install out in one step. The release guide keeps source, package, GitHub publication, and production deployment as separate facts.

This change adds no migration and no scheduled task: the wait, the migrate runner and the watchdog's boot grace all live in the existing scripts, so the logon task and the five-minute watchdog are still the only automatic work. The one-time `ops/redlib-relocate.ps1` is run by a person, not by a task.

The following acceptance work remains EXPLICITLY OPEN and is not closed by this release: fresh-machine human acceptance of the Windows install; the live provider matrix (configured-provider behaviour across the full provider set); five useful Dark Desk outcomes plus the September 3–8 replay; and the post-crash detached-child limitation. Production deployment and live-model proof are not asserted here. Nothing in this release was run against a real AI model, and no screenshot here was taken against the live paper.

Meeting capture specifically does not yet include: a provisional-to-revision cycle observed against a real capture (the re-check runs, but nothing inserts a link row, so it finds nothing to look at), and any path from a transcript to a story. Section 5 produces chunks, alignments and structured votes and deliberately does not draft.
