## Current release work — 2026-09-26

The current software version is [0.6.69](docs/releases/0.6.69.md): the news lane's lead matching and the machine upkeep. Until this release a story the scanner met twice in one run was filed twice, and a finding that matched a lead the editor had killed was dropped without a word even when it carried facts the killed lead never had. Every one of those cases is now decided before anything is written: two findings in the same run that are the same story become one lead with both source addresses kept; a strong match against a live lead still becomes **Possible duplicate** in Held; and a strong match against a killed lead is filed as **Developing: new facts on a story you killed** — with the old kill reason and a link to the killed lead beside it — only when the new finding brings a concrete date, dollar amount or number the killed lead lacked, while a killed lead whose facts have not changed is folded into the old one and the scan says so. An index, section or RSS feed address no longer counts as the same address as an article. The Queue's NEW row states **Looks already printed: \<headline\>** in place of the bare **≈ PRINTED** chip and offers a one-press **Kill as duplicate**; the Held tab carries a count badge; and **Compare** shows the two leads side by side with three presses — **Not a duplicate — move to New**, **Same story — kill this one**, **Newer facts — reopen the old one**. A killed lead's own page shows the lead, when and why it was killed, and a **Reopen** that keeps the record and records that the kill was undone. Machine upkeep in the same release: `ops/promote.ps1` and `installer/Install.ps1` hash files through `Get-TownReporterFileHash` rather than `Get-FileHash`, hand-named safety copies are carried to the second drive too, `ops/start-stage.ps1` starts the port-3100 test copy without touching the live paper, and the writing ladder's middle rung uses whichever model LM Studio has loaded, with `TOWNREPORTER_QWEN_MODEL` pinning one. The release guide keeps source, package, GitHub publication, and production deployment as separate facts.

This change adds one additive migration (`0094_lead_kill_record.sql`) and no scheduled task, service or program: it adds four nullable columns to `leads` — `kill_reason`, `kill_reason_url`, `killed_at` and `dup_kind` — and one index, none with a default, so a lead handled before this release reads as "not recorded" rather than as a decision nobody made. `ops/start-stage.ps1` is a script, not a task, and it starts the test copy only.

The previous release was [0.6.68](docs/releases/0.6.68.md): the backups and the alerts. Until that release a backup existed only as a side effect of a promotion — `ops\promote.ps1` was the only file in the tree that ran `pg_dump`, no scheduled task ran one, and the folder beside the app held 61 files and about 12.5 GB with nothing pruned and nothing on the second drive. `ops\lib-backup.ps1` now holds that one dump call and three callers use it: the nightly run driven by the five-minute watchdog the owner already has (after 2:00 AM local, when the newest backup is older than 20 hours, skipped while an editor job is running, never two at once), `ops\backup.ps1` — also the Control page's **Back up now** button — and `promote.ps1` itself. Every local backup not already verified on D: is copied, each copy written as `.partial` and renamed onto its real name only when its size **and** SHA-256 match, and the local folder is pruned to the newest three **only after** every local file is proved to be on D:. A missing or unwritable drive, a copy that fails its check, or a local file that is not a complete dump each delete nothing, say which file and why, and raise an alert; nothing is deleted from D: by any path, and a copy that would leave under 100 GB free is refused. A file counts as a backup only if it opened, closed, ended with the closing marker its opening marker promised, and passed a size floor. `ops\lib-alert.ps1` watches six conditions — the desk down over 10 minutes, the public site down over 10 minutes, the daily scan failed or not run by 8:00 AM when scheduled, the last good backup over 30 hours old, the offsite copy failing, the second drive short of room — firing once when each starts and once when it clears, into the Control page's **Attention** card, a Windows notification, and a phone push through ntfy that is off until `ALERT_NTFY_TOPIC` is set in `.env`. The page also gains **Last backup** and **Copy on D:**, both read from the reports the runs write rather than by enumerating a drive that may have gone to sleep, and no card is green when its probe did not answer. The watchdog reads `LastTaskResult` `267009` (`SCHED_S_TASK_RUNNING`) as a task still running rather than as a failure. That release added no migration and no scheduled task.

The release before that was [0.6.67](docs/releases/0.6.67.md): the editor's controls. A to-do the desk wrote itself, longer than the bound the desk read to-dos back at, used to refuse a save with raw validation output; the desk now clips what it writes at a word boundary, reads to-dos at that same bound, and normalises a stored one rather than refusing the round trip, and a failure in the editor's notes no longer blocks the printing of a valid draft. A headline an editor changed survives a **Redraft** and can be rewritten after the story has printed, from the story page and from **Published**, keeping the slug and every link, with the old headline, the account and the time in the append-only `article_headline_history` table; **Use the lead's headline** and **Suggest headlines** sit beside the box, and nothing is applied without a click. Publish reads **Publish in \<Section\>**, confirms that section for the version being printed in the same press, is disabled with the reason beside it when the scanner placed no section, and logs and counts on Stats every story whose section differed from the model's. It added one additive migration (`0093_editor_headline_control.sql`) and no scheduled task.

The following acceptance work remains EXPLICITLY OPEN and is not closed by this release: fresh-machine human acceptance of the Windows install; the live provider matrix (configured-provider behaviour across the full provider set); five useful Dark Desk outcomes plus the September 3–8 replay; and the post-crash detached-child limitation. Production deployment and live-model proof are not asserted here. Nothing in this release was run against a real AI model, and no screenshot here was taken against the live paper.

Meeting capture specifically does not yet include: a provisional-to-revision cycle observed against a real capture (the re-check runs, but nothing inserts a link row, so it finds nothing to look at), and any path from a transcript to a story. Section 5 produces chunks, alignments and structured votes and deliberately does not draft.
