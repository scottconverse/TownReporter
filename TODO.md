## Current release work — 2026-09-26

The current software version is [0.6.70](docs/releases/0.6.70.md): corrections that can fix the words, YouTube read through Google's own service, a screen that can clear the suggested sources, and a style check on a news draft. **The correction box no longer starts empty.** Opening a correction shows **What was wrong** and **What is right**, and **Suggest wording** asks the story model, through the same Automatic provider ladder every other call site uses, for one note in the paper's voice built only from those two lines and the story it can see and forbidden to add a fact of its own — read back with the same care as a headline suggestion, so a fenced block, a "Correction:" label, quotes, a lead-in sentence or anything past the first line comes off, and a list of options, a fragment or a paragraph longer than the schema allows is refused rather than offered. **Use a plain note** writes *An earlier version of this story said … In fact, …* on the desk with no model and no network call, and the note goes into the box, never onto the paper, until the editor presses **Publish correction**. **Also fix the story text** is a second checkbox, off unless the editor turns it on, that opens the printed body in an editor already holding the story as it printed; one press of **Publish correction** then publishes the note, updates the body and writes the old body to the append-only `article_body_history` in **one transaction**, the slug never moves, and a fix that is unchanged (including whitespace-only) or blank is refused with neither half written. **YouTube** is read through the YouTube Data API v3 when a key is saved on the Server page — encrypted with the same helper the custom AI connections use, write-only, sent in the `x-goog-api-key` header and never in a URL, a reply, a log line or an error — in at most three 1-unit calls (`channels.list`, `playlistItems.list`, `videos.list`) and never `search.list`; the channel tab HTML, the public feed and the yt-dlp listing stay as the fallback for no key, a refused key, a dead network, an unreadable reply or a day whose 10,000 units are already spent, a quota refusal is terminal for the Pacific day, and every receipt says which path ran. **Sources** gains **Suggested sources: N** — newest first, each row carrying the model's one sentence about the page and the suggester it came from — with **Anyone / The scan / The research pass / The Dark Desk / Not recorded** filters, per-row accept, reject and note, and batch accept/reject that commits as one transaction, with the section half still owner-only. **Style check** measures a news draft in code — unnamed attribution, importance-only sentences, participle tails, dressed-up verbs, filler words, synonym cycling, paste artifacts, tracking parameters and URL redirects, paragraphs over the form's cap, sentence-length variation and six-word repeats — and asks the model to repair only what the code found, at most two rounds, refusing a repair that flattens the sentence rhythm or changes any quotation, number, name or URL; the findings are stored with the draft and a draft that still has `fix` findings gains the review reason `style-audit-open`. The release guide keeps source, package, GitHub publication, and production deployment as separate facts.

This change adds three additive migrations (`0095_article_body_history.sql`, `0096_youtube_data_api.sql` and `0097_suggested_source_origin.sql`) and no scheduled task, service or program: 0095 creates the append-only `article_body_history` table a corrected body is written to (old body, new body, who, when and the correction that justified it); 0096 creates `youtube_api_settings` — one encrypted key per newsroom plus the Pacific day Google last refused for quota — and `youtube_api_usage`, units per newsroom per Pacific day; and 0097 adds seven nullable columns to `sources` (`proposed_reason`, `proposed_by`, `proposed_scan_run_id`, `proposed_lead_id`, `proposed_section`, `reviewed_at`, `review_note`) plus a partial index for the review list. None rewrites an existing row and none has a default, so everything that predates this release reads as "not recorded" rather than as a decision nobody made.

The previous release was [0.6.69](docs/releases/0.6.69.md): the news lane's lead matching and the machine upkeep. Until this release a story the scanner met twice in one run was filed twice, and a finding that matched a lead the editor had killed was dropped without a word even when it carried facts the killed lead never had. Every one of those cases is now decided before anything is written: two findings in the same run that are the same story become one lead with both source addresses kept; a strong match against a live lead still becomes **Possible duplicate** in Held; and a strong match against a killed lead is filed as **Developing: new facts on a story you killed** — with the old kill reason and a link to the killed lead beside it — only when the new finding brings a concrete date, dollar amount or number the killed lead lacked, while a killed lead whose facts have not changed is folded into the old one and the scan says so. An index, section or RSS feed address no longer counts as the same address as an article. The Queue's NEW row states **Looks already printed: \<headline\>** in place of the bare **≈ PRINTED** chip and offers a one-press **Kill as duplicate**; the Held tab carries a count badge; and **Compare** shows the two leads side by side with three presses — **Not a duplicate — move to New**, **Same story — kill this one**, **Newer facts — reopen the old one**. A killed lead's own page shows the lead, when and why it was killed, and a **Reopen** that keeps the record and records that the kill was undone. Machine upkeep in the same release: `ops/promote.ps1` and `installer/Install.ps1` hash files through `Get-TownReporterFileHash` rather than `Get-FileHash`, hand-named safety copies are carried to the second drive too, `ops/start-stage.ps1` starts the port-3100 test copy without touching the live paper, and the writing ladder's middle rung uses whichever model LM Studio has loaded, with `TOWNREPORTER_QWEN_MODEL` pinning one. That release added one additive migration (`0094_lead_kill_record.sql`) and no scheduled task.

The release before that was [0.6.68](docs/releases/0.6.68.md): the backups and the alerts. Until that release a backup existed only as a side effect of a promotion — `ops\promote.ps1` was the only file in the tree that ran `pg_dump`, no scheduled task ran one, and the folder beside the app held 61 files and about 12.5 GB with nothing pruned and nothing on the second drive. `ops\lib-backup.ps1` now holds that one dump call and three callers use it: the nightly run driven by the five-minute watchdog the owner already has (after 2:00 AM local, when the newest backup is older than 20 hours, skipped while an editor job is running, never two at once), `ops\backup.ps1` — also the Control page's **Back up now** button — and `promote.ps1` itself. Every local backup not already verified on D: is copied, each copy written as `.partial` and renamed onto its real name only when its size **and** SHA-256 match, and the local folder is pruned to the newest three **only after** every local file is proved to be on D:. A missing or unwritable drive, a copy that fails its check, or a local file that is not a complete dump each delete nothing, say which file and why, and raise an alert; nothing is deleted from D: by any path, and a copy that would leave under 100 GB free is refused. A file counts as a backup only if it opened, closed, ended with the closing marker its opening marker promised, and passed a size floor. `ops\lib-alert.ps1` watches six conditions — the desk down over 10 minutes, the public site down over 10 minutes, the daily scan failed or not run by 8:00 AM when scheduled, the last good backup over 30 hours old, the offsite copy failing, the second drive short of room — firing once when each starts and once when it clears, into the Control page's **Attention** card, a Windows notification, and a phone push through ntfy that is off until `ALERT_NTFY_TOPIC` is set in `.env`. The page also gains **Last backup** and **Copy on D:**, both read from the reports the runs write rather than by enumerating a drive that may have gone to sleep, and no card is green when its probe did not answer. The watchdog reads `LastTaskResult` `267009` (`SCHED_S_TASK_RUNNING`) as a task still running rather than as a failure. That release added no migration and no scheduled task.
