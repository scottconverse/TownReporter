This release is the daily scan on **Automatic**.

## What an editor can do now

### The schedule can be left on Automatic

The daily ordinary scan on Server no longer has to name one provider before it
can be saved. The picker offers **Automatic**, the same first option the Story
and Scan pickers carry, and a newsroom that has never saved the schedule opens
on it. Automatic walks the writing ladder already described for stories,
scans and Dark Desk: DeepSeek v4.1 Flash first, then Qwen 3.6 35B **on this
computer, when it is loaded**, then Codex Terra.

A named choice is still available and still tried first: Codex Astra, Sol,
Terra or Luna; Claude Fable, Opus, Sonnet or Haiku; the selected local model;
or a saved Custom AI connection. A schedule saved before this release keeps the
model it names. Nothing rewrites a stored choice on its own — the owner
switches it to Automatic by hand.

### The run record names the model that actually ran

Because a scheduled run stores the model it will use before its job is queued,
Automatic is resolved to a ready model at that point, and the run records what
was requested and what resolved. The Daily scan panel shows the pair —
`Model: Automatic → DeepSeek v4.1 Flash` — and a run that had to move keeps its
switch note, as before.

## What changed for safety

- **Automatic is resolved before the run is reserved, not at call time.** The
  reservation and the scan run are written together with the resolved model in
  their snapshot, so a run cannot start on a model its own record does not
  name.
- **No stored runtime is rewritten.** A policy that holds a named model, a
  local model or a saved Custom AI connection keeps exactly that value, and the
  stored row still reads what the owner saved after a reload.
- **A resolved model is not a hand pick.** The rungs Automatic resolves to are
  not options in any menu and cannot be stored as one; a hand-picked model
  fails over along the named-model path it has always used, never onto a rung.
- **A content refusal is still terminal**, and a technical failure can still
  move only unfinished work.

## Migrations

This change adds no migration. `daily_scan_policies.runtime` is a plain text
column (`migrations/0050_daily_scan.sql:7`), so it already holds the value the
policy now stores.

## Known limits

- **Nothing in this release was run against a real AI model**, and no part of
  this work ran against the live paper.
- **The browser walk does not assert the reserved job's own outcome.** The
  model receipt is written by the scheduler before the job is queued, and that
  receipt is what the walk reads; the source fetch and the writing pass that
  follow it are not proved by it.
- **Automatic on the scan is a resolution, not a live choice.** The rung is
  chosen when the run is reserved, so a provider that becomes unavailable
  between reservation and the call is handled by the ordinary mid-run failover
  and recorded as a switch, not by re-reading the ladder from the top.
- **Production deployment is not asserted here.** A repository version, a tag,
  or a GitHub release does not establish what the live paper is running.
