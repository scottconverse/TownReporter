This release is the daily scan on **Automatic** — and, alongside it, Reddit
read as a Reddit source in the scan, one press reading a long scanned packet to
the end, and a dark-mode first frame that is dark.

## What an editor can do now

### The schedule can be left on Automatic

The daily ordinary scan on Server no longer has to name one provider before it
can be saved. The picker offers **Automatic**, the same first option the Story
and Scan pickers carry, and a newsroom that has never saved the schedule opens
on it. Automatic walks the writing ladder already described for stories,
scans and Dark Desk: DeepSeek v4.1 Flash first, then Qwen 3.6 35B **on this
computer, when it is loaded**, then Codex Terra.

A named choice is still available and still tried first: Codex Astra, Sol,
Terra or Luna; Claude Fable, Opus, Sonnet or Haiku; the selected local model;
or a saved Custom AI connection.

### A saved schedule keeps the model it names

Nothing rewrites a stored choice on its own. A schedule saved before this
release stays on the model, the local model or the saved Custom AI connection
it names, and the stored row still reads what the owner saved after a reload.
The owner switches it to Automatic by hand, in **Scan settings**.

### The run record names the model that actually ran

Because a scheduled run stores the model it will use before its job is queued,
Automatic is resolved to a ready model at that point, and the run records what
was requested and what resolved. The Daily scan panel shows the pair —
`Model: Automatic → DeepSeek v4.1 Flash` — and a run that had to move mid-call
keeps its switch note, as before.

### A scan that fetched nothing says so

A run that fetched no source text builds no analysis batches, and it used to
report that the writing pass returned nothing usable. It now reports the fetch
instead: **Scan fetched no source text, so no writing pass ran.**, naming the
first source that failed. The model-shaped message is kept for the different
case where batches did run and their reply could not be read.

### A Reddit source is read as a Reddit source

A subreddit added to a scan used to be fetched like any other page. Reddit hands
its app shell to a reader that is not a browser, so there was almost no readable
text in what came back and the source contributed nothing to the scan.

A Reddit source is now read through the subreddit's own `.rss` feed. Each recent
post arrives as its headline, its body, the post's own permalink, its author and
its time, and those bodies reach the writing pass as the author wrote them.

When the local **Redlib** reader is installed and answering, the desk also reads
up to three top comments of each discussion it picked, so a story can carry what
the residents who replied said and not only what the original poster said. That
is the difference Redlib makes: it is the only way this desk reads a Reddit
thread in full.

Every word of it is marked for what it is. A Reddit source's text opens by
saying these are **residents' own accounts, unverified — a lead, not a
citation**, and each lead carries its own permalink back to the thread it came
from. This is Tier C material: something worth looking into, never a fact to
publish as one.

The source also says what it actually got, rather than leaving the editor to
assume. One coverage line reports it:

- `Redlib read 3 selected discussions in full.` — the local reader answered for
  every discussion the desk picked;
- `Redlib read 3 selected discussions; Reddit omitted some comments.` — it
  answered, but Reddit did not return everything on those pages;
- `Redlib did not answer; RSS excerpts were used.` — Redlib is not running. The
  posts are still there and those discussions carry no comments at all, which
  the source text states instead of filling the gap from memory.

Comments are read only from the Redlib running on the owner's own machine, on
loopback. Public Redlib instances are deliberately not used.

### One press reads a long scanned packet to the end

Attaching a scanned council packet longer than twelve pages and pressing
**Redraft** used to read twelve of them, stop with a red **Retry to continue**,
and start no draft at all — and because that stop aborted the job, any document
attached after the packet was never read either. One press now keeps reading the
same document, batch after batch, with the desk showing how far it has got
(`Reading packet.pdf: page 13 of 13`), and it always goes on to the documents
after it. The per-request cap on vision work is unchanged — one reading call
still handles at most twelve pages (`src/lib/news/ocr-batches.ts:9`) — but the
job no longer stops between calls; it reads under a budget sized for real
council packets, up to 300 pages and 20 minutes per document and 600 pages and
60 minutes per redraft.

If a document still cannot be finished inside that budget, the redraft is not
aborted. It drafts from every page that was read and shows a warning naming the
document and the pages used — `packet.pdf (7 of 13 pages read)` — with a
**Read the rest** button beside it. That button resumes from the pages already
retained, so an editor never has to guess how many times to press.

### Dark mode no longer flashes white

A screen change, the "Opening the desk" screen, an error screen or a reload in
dark mode paints dark on the first frame. The saved Light/Dark and
Normal/Large choices are applied by a small script in the page head, before
anything paints, and every dark palette in the product reads the two attributes
that script stamps on the page rather than deciding for itself. The public
paper's dark reading mode is applied the same way.

The saved choice is read from where the desk already kept it, not from a
second store: a companion cookie would be one more thing that can disagree with
the setting the owner actually chose, and a stale one renders light — the same
flash by another route. Nothing the reader sees is rendered twice either, so
there is no mismatch between the first frame and the one after it.

Reading the saved file for this fix turned up a second, separate defect in the
same area. The "Opening the desk" screen was painting **black** where the desk
is dark green-grey: a legacy letterpress rule was beating the screen's own
background rule on specificity, so the first fix was dead code for that one
screen. Dropping the appearance attribute from the legacy rule repaired it. The
fix is checked by measurement rather than by inspection: a browser walk samples
the colour every frame is about to paint, on a hard reload of every desk screen
and on a click between them, in dark and in light, and requires every frame to
be the right one — including a control pass that deliberately breaks the
attribute and requires the probe to report the other colour.

## What the owner can do on the machine

Two services a self-hosted install may have — the local Redlib reader and Ollama
— were invisible to everything that starts, stops and checks this machine. They
are now part of it, and their absence is still a supported state rather than a
fault.

### The Control menu has an entry for the reader

`ops/TownReporter Control.cmd` — double-click, pick a number — has a sixth
entry: **Restart the Reddit reader**, "when Reddit threads read as headlines
only". It runs `ops/redlib.ps1 restart`, which waits for the reader to actually
answer Reddit, so it can take a minute; the paper is not affected either way.
The menu still cannot print, publish or delete anything.

### The check says whether each one is up, and whether it matters

`ops/status.ps1` — menu option 1, and usable on its own when the paper is down —
now prints two more lines. `Reddit reader (Redlib)` reads `up`, or `down - the
paper reads Reddit through RSS alone`, or that none is installed, or that it is
switched off. It is a **NOTE**, never a fault: the paper serves either way.
`DeepSeek (via Ollama)` reads `ready`, or `Ollama not running - the paper will
use the next model`, or `starting up`, or that the model is not on this machine.
Ollama is the first rung of Automatic's ladder, so its absence is a route the
scan already knows how to take.

### Starting, stopping, and the watchdog

Starting the paper now brings the reader up with it, detached and last, so a
slow reader cannot hold the logon task up. Stopping the paper stops the reader
with it, through the pid file that reader's own installation wrote — never by
image name, and refusing rather than guessing when the recorded pid is not a
Redlib. The five-minute watchdog starts whichever of the two is down, and it
**never stops** either one: a model may be mid-draft, and a reader that is
answering is left alone. LM Studio is not started, probed or unloaded by any of
it.

Both services can be left out entirely. `TOWNREPORTER_REDLIB=0` and
`TOWNREPORTER_OLLAMA=0` in `.env` make every one of these scripts leave that
service alone.

### After a reboot

No new scheduled task was added. The existing logon task starts the paper and
then the reader, and the existing five-minute watchdog reaches both afterwards;
Ollama is started by the owner's own Startup shortcut, by Windows and not by
this project. The full order — Postgres, the paper, the reader, Ollama, the
tunnel, the watchdog, and LM Studio, which nothing here touches — is tabulated
in `SELF-HOSTING.md`, with the same table in `docs/setup.md`.

One honest caveat from the machine this was built on: compiling Redlib from its
pinned commit needs its BoringSSL configured with `-DOPENSSL_NO_ASM=YES`, and
that define does not reach cmake once a `CMakeCache.txt` exists. `ops/redlib.ps1
setup` hands the same define to the compiler instead. It affects that build only
and has no effect at runtime.

## What changed for safety

- **Automatic is resolved before the run is reserved, not at call time.** The
  reservation and the scan run are written together with the resolved model in
  their snapshot, so a run cannot start on a model its own record does not
  name.
- **No stored runtime is rewritten.** A policy that holds a named model, a
  local model or a saved Custom AI connection keeps exactly that value.
- **A resolved model is not a hand pick.** The rungs Automatic resolves to are
  not options in any menu and cannot be stored as one; a hand-picked model
  fails over along the named-model path it has always used, never onto a rung.
- **A content refusal is still terminal**, and a technical failure can still
  move only unfinished work.
- **The two new services cannot fail the paper.** Every Redlib and Ollama
  section of the start, stop and watchdog scripts is wrapped, and each one's
  failure ends by saying the paper is unaffected. `ops/lib-ollama.ps1` contains
  no `Stop-Process` at all — the watchdog starts Ollama and never stops it,
  because a model may be mid-draft.
- **Nothing is stopped by image name.** The Reddit reader is stopped through
  the pid file its own installation wrote, and the stop refuses when the
  recorded pid is not the executable that installation recorded, rather than
  guessing at what to kill. LM Studio and its models are not started, probed or
  unloaded by any of this.
- **No seventh scheduled task.** The existing logon task and the existing
  five-minute watchdog already reach both services, and a dedicated task would
  be a second starter racing the first. The task list stays at six, asserted by
  a test that counts them.

## Migrations

This change adds no migration. `daily_scan_policies.runtime` is a plain text
column (`migrations/0050_daily_scan.sql:7`), so it already holds the value the
policy now stores, including a value written before this release.

Reading a long document adds one column, `story_documents.read_pages`
(`migrations/0092_story_document_partial_read.sql`), which records how many
pages a partly read document kept. It is nullable and null for every row that
was not left partly read, so an existing row reads as complete, and the boot
path adds the column the same way (`src/lib/news/story-documents.server.ts:90`).

The Reddit source work and the appearance fix add no migration. A Reddit
source's text and its coverage line are produced when the source is read and
nothing new about them is stored, and the saved appearance is read from where
the desk already kept it.

## Known limits

- **Nothing in this release was run against a real AI model**, and nothing in
  it writes to the live paper. The browser walks and the focused tests run
  against a stub endpoint on the loopback address. Two read-only reads were
  taken while building it — one live fetch of a real subreddit through the new
  Reddit read, and one `ops/status.ps1` check of the live paper, which reported
  `Dry run. Nothing was started, stopped or changed.` — and neither wrote
  anything.
- **The walk makes one outbound request to `example.com`.** A scan source has
  to be a public HTTP URL the URL guard accepts, and the guard refuses
  loopback, private and unresolvable hosts with no escape hatch, so a walk that
  must fetch real source text uses that one public page. It is an ordinary
  read of a page that is not the paper's own source, and it is the only
  outbound request the walk makes.
- **Automatic on the scan is a resolution, not a live choice.** The rung is
  chosen when the run is reserved, so a provider that becomes unavailable
  between reservation and the call is handled by the ordinary mid-run failover
  and recorded as a switch, not by re-reading the ladder from the top.
- **The long-packet walk attaches on the Write page, not in the workspace.**
  `scripts/redraft-scan-e2e.mjs` drives two presses rather than one: it attaches
  the 13-page scanned packet and a second document on the Write page (the only
  page that renders an attach control — an attempt to attach from the story
  workspace timed out, and the Sources tab lists documents without one), presses
  **Write draft** once, and watches that press read both sources page by page
  across the twelve-page batch boundary; it then presses **Redraft** on the
  saved story, which is the press this release is about, and watches the
  redraft rewrite from both sources without re-reading a page. Both screens
  were captured at 1280 in light and dark.
- **A Reddit source is Tier C by construction.** Posts and comments are
  residents' own unverified accounts. The source text marks them as such, every
  lead carries its own permalink back to its thread, and nothing in the scan
  corroborates any of it against a second source: resident concerns stay
  comments under the lead rather than becoming claims.
- **Comments come only from a local Redlib, and the coverage line is a report
  rather than a guarantee.** With Redlib down, the source still carries the
  subreddit's recent posts, states `Redlib did not answer; RSS excerpts were
  used.`, and carries no comments at all; with Redlib up, a discussion Reddit
  does not return in full is named as such. The line says what was retrieved,
  not that the thread was read. Public Redlib instances are deliberately not
  used, and what the subreddit's own feed carries is what is read.
- **The Reddit path is covered by tests, not by a browser walk.** The
  subreddit-as-a-source behaviour is asserted in the standard test suite against
  a recorded feed fixture, with a stub Redlib answering and with it down. One
  read-only live read of a real subreddit was taken while building it; no scan
  in this release was run against real Reddit and then published, and no walk
  drives this path in a browser.
- **Production deployment is not asserted here.** A repository version, a tag,
  or a GitHub release does not establish what the live paper is running.

## Evidence boundary

The source tree and a locally built candidate can prove implementation, tests,
migrations, browser behavior, and package contents. Only the GitHub release page
can prove publication, and only a separately authorized production verification
can prove deployment. This note does not turn one of those facts into another.
