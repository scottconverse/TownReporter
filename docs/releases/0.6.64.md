This release is the daily scan on **Automatic**.

## What an editor can do now

### The schedule can be left on Automatic

The daily ordinary scan on Server no longer has to name one provider before it
can be saved. The picker offers **Automatic**, the same first option the Story
and Scan pickers carry, and a newsroom that has never saved the schedule opens
on it. Automatic walks the writing ladder already described for stories,
scans and Dark Desk: DeepSeek v4.1 Flash first, then Qwen 3.6 35B **on this
computer, when it is loaded**, then Codex Terra.

A named choice is still available and still tried first: Codex Astra, Sol,
Terra or Luna; Claude Fable, Opus, Sonnet or Haiku; the selected local model;
or a saved Custom AI connection.

### A saved schedule keeps the model it names

Nothing rewrites a stored choice on its own. A schedule saved before this
release stays on the model, the local model or the saved Custom AI connection
it names, and the stored row still reads what the owner saved after a reload.
The owner switches it to Automatic by hand, in **Scan settings**.

### The run record names the model that actually ran

Because a scheduled run stores the model it will use before its job is queued,
Automatic is resolved to a ready model at that point, and the run records what
was requested and what resolved. The Daily scan panel shows the pair —
`Model: Automatic → DeepSeek v4.1 Flash` — and a run that had to move mid-call
keeps its switch note, as before.

### A scan that fetched nothing says so

A run that fetched no source text builds no analysis batches, and it used to
report that the writing pass returned nothing usable. It now reports the fetch
instead: **Scan fetched no source text, so no writing pass ran.**, naming the
first source that failed. The model-shaped message is kept for the different
case where batches did run and their reply could not be read.

### One press reads a long scanned packet to the end

Attaching a scanned council packet longer than twelve pages and pressing
**Redraft** used to read twelve of them, stop with a red **Retry to continue**,
and start no draft at all — and because that stop aborted the job, any document
attached after the packet was never read either. One press now keeps reading the
same document, batch after batch, with the desk showing how far it has got
(`Reading packet.pdf: page 13 of 13`), and it always goes on to the documents
after it. The per-request cap on vision work is unchanged — one reading call
still handles at most twelve pages (`src/lib/news/ocr-batches.ts:9`) — but the
job no longer stops between calls; it reads under a budget sized for real
council packets, up to 300 pages and 20 minutes per document and 600 pages and
60 minutes per redraft.

If a document still cannot be finished inside that budget, the redraft is not
aborted. It drafts from every page that was read and shows a warning naming the
document and the pages used — `packet.pdf (7 of 13 pages read)` — with a
**Read the rest** button beside it. That button resumes from the pages already
retained, so an editor never has to guess how many times to press.

### Dark mode no longer flashes white

A screen change, the "Opening the desk" screen, an error screen or a reload in
dark mode paints dark on the first frame: the saved Light/Dark and Normal/Large
choices are applied by a small script in the page head, before anything paints,
and the public paper's dark reading mode is applied the same way.

## What changed for safety

- **Automatic is resolved before the run is reserved, not at call time.** The
  reservation and the scan run are written together with the resolved model in
  their snapshot, so a run cannot start on a model its own record does not
  name.
- **No stored runtime is rewritten.** A policy that holds a named model, a
  local model or a saved Custom AI connection keeps exactly that value.
- **A resolved model is not a hand pick.** The rungs Automatic resolves to are
  not options in any menu and cannot be stored as one; a hand-picked model
  fails over along the named-model path it has always used, never onto a rung.
- **A content refusal is still terminal**, and a technical failure can still
  move only unfinished work.

## Migrations

This change adds no migration. `daily_scan_policies.runtime` is a plain text
column (`migrations/0050_daily_scan.sql:7`), so it already holds the value the
policy now stores, including a value written before this release.

Reading a long document adds one column, `story_documents.read_pages`
(`migrations/0092_story_document_partial_read.sql`), which records how many
pages a partly read document kept. It is nullable and null for every row that
was not left partly read, so an existing row reads as complete, and the boot
path adds the column the same way (`src/lib/news/story-documents.server.ts:90`).

## Known limits

- **Nothing in this release was run against a real AI model**, and no part of
  this work ran against the live paper. The browser walk and the focused tests
  run against a stub endpoint on the loopback address.
- **The walk makes one outbound request to `example.com`.** A scan source has
  to be a public HTTP URL the URL guard accepts, and the guard refuses
  loopback, private and unresolvable hosts with no escape hatch, so a walk that
  must fetch real source text uses that one public page. It is an ordinary
  read of a page that is not the paper's own source, and it is the only
  outbound request the walk makes.
- **Automatic on the scan is a resolution, not a live choice.** The rung is
  chosen when the run is reserved, so a provider that becomes unavailable
  between reservation and the call is handled by the ordinary mid-run failover
  and recorded as a switch, not by re-reading the ladder from the top.
- **The long-packet walk attaches on the Write page, not in the workspace.**
  `scripts/redraft-scan-e2e.mjs` drives two presses rather than one: it attaches
  the 13-page scanned packet and a second document on the Write page (the only
  page that renders an attach control — an attempt to attach from the story
  workspace timed out, and the Sources tab lists documents without one), presses
  **Write draft** once, and watches that press read both sources page by page
  across the twelve-page batch boundary; it then presses **Redraft** on the
  saved story, which is the press this release is about, and watches the
  redraft rewrite from both sources without re-reading a page. Both screens
  were captured at 1280 in light and dark.
- **Production deployment is not asserted here.** A repository version, a tag,
  or a GitHub release does not establish what the live paper is running.
