This release is **follow-ups that keep working, the editor's dialogs built, a
Stats screen that counts readers without naming one, and a section row that
stays on one line**. A follow-up stops being only a list of who was asked and
what they owe: an editor can now start an agent that watches a page, searches
public records or waits for a meeting agenda, and writes what it finds into the
story's reporting notes. The nine dialogs the redesign draws for the editor are
built — and **no screen mounts them yet**, which this note says plainly rather
than leaving to be discovered. **Stats** opens at `/desk/stats`, on a reading
beacon whose tables carry no column that could name a reader. And the paper's
section links now sit on one line at every width, with **Dark mode** in the top
bar. **No model was called and no model was loaded to build or check this
release** — every check ran against fakes, fake servers, a fake clock, and
PGlite.

## Follow-ups can now be agents, not just asks

Until this release every follow-up was the same thing: who was asked, what they
owe, when it is due, and the editor drove all of it — nudging, recording the
reply, dropping it. **Follow-ups** (`/desk/follow-ups`) keeps those rows and
adds a second kind beside them. A follow-up started with **+ New AI follow-up**
names a question and a method, and from then on the desk works it on a schedule
and reports what it finds.

- **Re-check pages** watches the pages the editor names and says when one of
  them changes. It is the page-watch engine the desk already had, not a second
  crawler: the same capture, the same OCR, the same "unchanged / changed /
  refused" vocabulary.
- **Search public records** runs the desk's own web search for the question and
  has a model read the hits and decide whether any of them actually answers it.
- **Watch for next agenda** watches a meeting body's portal and reports when a
  new agenda is posted. PrimeGov portals today, which is what the daily scan's
  meeting capture already reads.

Each card belongs to one of four filters — **Active**, **Found something**,
**Could not check**, **Stopped** — carries a 4px left border in the state's
color, and shows the method and its cadence ("Re-check pages · every 2 hours"),
the question in the editor's own words, the latest result, the story it is
linked to, and its next check.

## "Nothing changed" and "could not check" are different cards

This is the point of the screen, and it is why the state is five values rather
than a boolean "found something". An agent that got where it was going and
found the page unchanged is **healthy** — "Checked · no change". An agent that
could not read the page at all is **not**: "Could not check", with the real
reason on the card ("The page timed out.", "This build can only watch PrimeGov
portals.") and a **Retry now** button. A follow-up that has been quietly
failing for a week must not look like one that has been quietly working.

## A finding goes to the story's reporting notes. It never publishes

When an agent finds something it writes one line into that story's **reporting
notes**, through the same column and the same helpers the notes panel uses, and
the card's **Review finding** button goes there. Nothing in this feature writes
an article, a draft or a lead — there is no publish path out of it at all. The
screen says so in its first paragraph, and that is the sentence worth keeping.

## The editor's dialogs are built, and no screen mounts them yet

Phase 4 of the redesign builds the nine dialogs the design draws for the
editor — **New story** in its three tabs (write it with AI, write it myself,
paste it in), **Add a lead**, **Add sources to watch** with a preview table
that shows what will be added before it adds it, **Add to this story** where
the first press writes nothing and the second saves exactly the bytes the
editor read, **Start a Dark Desk file**, **Hold this lead**, **Headline**, the
**More ▾** lead-row menu, and the **kill pattern** under a source. Each is an
exported component under `src/components/dialogs/`.

**Nothing an editor can reach today changed.** The screens that mount these
dialogs are other phases' work, so this release ships the dialogs and says so.
What is proven here is each dialog's own logic: what it plans, what it refuses
with, and that a cancelled dialog leaves state exactly as it opened.

Six server functions stand behind them — `addLead`, `holdLead`,
`sourceKillPattern`, `findSources`, `weaveIntoStory`, `chooseHeadline` — each
with a schema beside it. `weaveIntoStory`'s mode is required, so a request that
forgot to say "paste in as-is" cannot default into a model call. Every
`perform*` takes its SQL, its chat call and its writers from one injected
dependencies object, so the decisions are tested with a fake database and a
counting model — which is how "the model is not asked again on the confirm
press" is asserted rather than described, and how "the kill pattern writes
nothing" is asserted as zero writes.

The kill pattern prints **both** numbers always — how many leads were killed
from a source and how many of those were killed for a bad-source reason —
because a source with nine kills and none of them its fault is a source to
keep. It is read-only by construction.

## Stats, and the privacy rule it is built on

**Stats** opens at `/desk/stats` on a range control — Today / 7 days / 30 days
/ 12 months — with Export CSV beside it, then the live panel, the summary
cells, the thirty-day chart, the story read-through table, the three bar
panels, the hour-by-day heatmap with its one-line takeaway, the trust signals,
and the two panels that were already there. Those last two, **Section chosen by
hand** and **Saved reports**, are untouched; the rest of the page is new.

**"Reading right now"** is computed in memory on the server over a rolling
thirty-minute window and is never written with any key that could name a
reader. Two consequences an editor should know: the window empties when the
server restarts, and on a site running more than one server process each
process sees only its own readers. Nothing on the screen merges them.

**Visits** counts page loads whose referrer is not this paper's own host. An
empty referrer counts as outside — a link pasted into a text message looks the
same as a bookmark, and the page says so. Arriving from one of our own story
paths is **Read another story**, a recirculation and not a visit. **Left
without reading** is a load whose active reading time was under ten seconds.

There is **no daily unique count anywhere**, because computing one would
require exactly the identifier the rule forbids; **returning readers** is not
measured, and the panel under **What we never collect** says so in those words.
The location panel prints that **the paper does not look up where readers are**
and offers nothing else: there is no GeoIP database in this release, and the IP
is not read for any purpose.

## The paper's section links, and Dark mode in the top bar

The paper prints 21 sections, and the row of section links wrapped to three
lines at 1280 on real data. It is now one line at every width. The nav decides
where to cut by **measuring the links it has just rendered** rather than by a
fixed count, so the row stays one line whatever the labels and the font do;
what does not fit goes behind a 44px **More sections** disclosure that is
keyboard reachable, reports `aria-expanded`, and returns focus to itself on
close. Below 900px the nav is hidden and the existing "Explore the
publication" menu carries the whole list, so the mobile path is unchanged.

The article page wrapped its section links onto a second line **under** the
logo; both rows now render the same nav, on the masthead row beside the
wordmark. **Dark mode** joins Search, Saved and Editor's desk in the top bar as
a one-press switch. It flips the same reader preference the reading dialog's
Light/Dark pair writes, says `aria-pressed`, and names the mode the press will
give you.

That button also fixed the reason the toggle did not repaint the **article**
page. `refreshReader()` re-renders the appearance provider, which is the
button's own ancestor, and that render reads the stored dark bit for itself;
React renders the ancestor first, so a write queued inside the state updater
had not happened yet and the provider re-read the old value. Writing storage in
the handler, before any state change is queued, makes the value the provider
reads the value it just published. Measured on the built paper, the article
page had stayed dark at all five widths; the front page had passed only by luck
of an extra render.

## What a reader sees

A section row that stays on one line, with **More sections** when the row is
full and **Dark mode** in the top bar — and a light-mode switch on the article
page that now actually repaints it. Nothing else: no feed changes and no
change to the words of any story.

## Migrations

Two additive migrations, and **they run on start**:

- **`0101_ai_follow_ups.sql`** adds eight nullable columns to `follow_ups` —
  the agent kind, its targets, its schedule, its model pick, its last and next
  run, its last state and its finding.
- **`0102` is not used.**
- **`0103_read_hourly.sql`** creates two hourly aggregate tables, `read_hourly`
  and `trust_signals_hourly`, and neither has a column for an IP, a user agent,
  a cookie, a session or any id.

## Compatibility

No existing behaviour is removed and nothing changes shape. `agent_kind` is
null on every follow-up row written before this migration and those rows keep
rendering exactly as they did, as **Manual asks**; the status check is widened
to the union of the old and new vocabularies rather than rewritten, so an old
row cannot fail its constraint because a new build shipped. The editor's
dialogs add **no migration at all** — the hold reason rides in the lead's
existing notes, because there is no hold column today and adding one would mean
touching every hand-built `leads` table for a value nothing queries.

Follow-up runs are **in-app jobs**, not a new service: a `follow-up` job in
`desk_jobs`, reporting progress through the job card and honoring the editor's
Stop. Scheduling is the daily scan's existing pattern. Three rules are enforced
in one place: follow-ups run **one at a time**, **never alongside a running
draft**, and a `running` row whose worker died is put back after twenty minutes
— twice the run's own hard cap, so a slow-but-alive run cannot be mistaken for
a dead one. A refusal is reported in words rather than silently doing nothing.

**No new scheduled task, service, program, port or installer step.**

**Limits.** The nine dialogs are exercised by their own tests and rendered in
the browser at 1280 in light and dark, but **no screen mounts them**, so no

exercised on PGlite with migrations applied from disk; **PostgreSQL was not
started and no production database was contacted**, and the schema-parity test

agent's own dependency object is the whole outside world in that feature, and
the tests drive found, no-change and could-not-check through fakes. Follow-up
scheduling is PrimeGov-only for the agenda method, and the reading counts are
per server process, as above. Fresh-machine human acceptance of the Windows
install, the live provider matrix, and the live-model proof remain open and are
not asserted here.
