This release is **the news lane's lead matching, and the upkeep that keeps the
machine honest**. Two questions came out of the Queue: *"Do I miss the real 2nd
story?"*, and why a lead could sit at NEW under a cryptic **≈ PRINTED** badge
whose **POSSIBLE DUPLICATE · COMPARE** link opened a page that only said *"This
lead was killed. Nothing to draft."* Both were real. This release answers them,
and fixes four pieces of machine upkeep found while the paper was being watched.

## Nothing the scan finds is thrown away

When the scanner finds a story it already has, there are now three cases instead
of two:

- **The same story twice in one scan run** becomes **one** lead, with both source
  addresses kept on it. This is the case that filed leads 207 and 212 on
  2026-09-25 — the same headline, city page and second, filed twice, one of them
  printed as article 73 while the other sat at NEW.
- **A strong match against a live lead** behaves as before: the lead is held as a
  possible duplicate and its "came back" count goes up.
- **A strong match against a killed lead now depends on the facts.** If the new
  finding carries a concrete fact the killed lead did not have — a **date**, a
  **dollar amount** or a **number** — it is filed in **Held**, labelled
  *"Developing: new facts on a story you killed"*, linked to the old lead, with
  the old kill reason shown beside it. A *reworded* why is not a new fact: the
  scan rewords its own why nearly every time it re-finds a story, so counting new
  words refiled almost every killed repeat — the opposite of what was asked. A
  lead whose headline recurs and whose concrete facts are the same is still
  folded into the old one, and the scan summary says so in those words.

**An index or section page is not a shared source.** A crime list, `/news/`, a
`/category/…` page, a site root or an RSS feed has no article slug, so it no
longer counts as "the same URL" when the scanner decides two findings are the
same story. This is the case behind leads 218 and 209, which both cited the Daily
Camera crime index rather than an article.

## The Queue says what it means

- The NEW row no longer shows **≈ PRINTED**. It says **"Looks already printed:
  \<headline\>"**, links to the article, and offers a one-press **Kill as
  duplicate** that records the reason ("Duplicate of \<headline\>") and a link to
  the piece it was killed against. Saving, saved and failed each say so on the
  page.
- The **Held** tab carries a count badge, so held work is not hidden behind a tab.
- A killed lead that has come back shows **"Came back N times"** on its row.

## Compare is a comparison

**Compare** opens a side-by-side view of both leads on the page you are already
on: headline, why, sources, filed date, status and kill record for each. Three
presses, each of which gives visible feedback:

- **Not a duplicate — move to New**
- **Same story — kill this one**
- **Newer facts — reopen the old one**

A press the desk refuses says so in a sentence, in the editor's words rather than
the server's. Reopening is offered only for a killed lead and explains itself when
it is not applicable.

## A killed lead still shows what it was

A killed lead's page replaces *"This lead was killed. Nothing to draft."* with the
lead itself — headline, why, sources, when it was filed — plus when and why it was
killed and a **Reopen** button. After a reopen the record stays and says the kill
was undone, because a page that silently forgets a kill is the same hidden state
this release is about.

## The machine keeps itself up

- **The hash check no longer needs a PowerShell module.** `ops/promote.ps1` and
  `installer/Install.ps1` checked a downloaded file with `Get-FileHash`, which is
  missing from a Windows PowerShell 5.1 session whose `PSModulePath` came from
  PowerShell 7 — measured 2026-09-26 — so a promotion or an install stopped at
  the first hash. Both now hash with the same .NET SHA-256 code `ops/lib-backup.ps1`
  already used.
- **Hand-named safety copies get an off-disk copy too.** A copy named by hand —
  `townreporter_2026-09-24_1510_pre-provider-recovery.sql`, the kind made before
  touching anything risky — was never copied anywhere. Every other `*.sql` and
  `*.dump` in the local backup folder now goes to `<offsite>\other-safety-copies\`
  with the same discipline as the nightly series: written as `.partial`, verified
  by size and SHA-256, then renamed onto its real name. Nothing on the second
  drive is deleted by any code path.
- **The test copy on 3100 comes back after a reboot.** The rule is that the test
  copy is always running, but nothing started it at boot. The new
  `ops/start-stage.ps1` is **start-only** — it starts the copy that was already
  staged and never restores a backup over it — and it is reached by hand, by a
  **Start the test copy** button on the Control page, and by the watchdog that
  already runs every five minutes (no new scheduled task). It starts only when
  3100 is not answering *and* the paper on 3000 is healthy, at most once per 30
  minutes, and it checks what holds 3100 before touching it: anything that is not
  ours is left alone.
- **The copy on 3100 is found wherever it was staged.** The live checkout had no
  state file, because a build never happens in production and the copy is staged
  from a worker or dev checkout. `ops/stage.ps1` now writes one small file
  outside every checkout — `%LOCALAPPDATA%\TownReporter\staged-copy.json` —
  naming the checkout, port, commit, version, database and time of the copy it
  brought up, and `ops\stage.ps1 -Stop` removes it. The watchdog, the button and
  the Control page's 3100 card all follow that pointer through one gate, and it
  is not trusted on sight: the path must be absolute, under
  `C:\Users\scott\Desktop\Code\`, a TownReporter checkout that is not the live
  paper, with an `ops\.stage.json` that agrees on port and commit plus a real
  build. Anything else starts nothing and says the plain reason once. No pointer
  at all is silence.
- **"Local model" means whatever LM Studio has loaded.** The middle rung of the
  writing ladder was fixed to `halo/qwen3.6-35b-a3b`, so it skipped all day while
  another model was loaded. It now reads LM Studio's own load state — the native
  `/api/v0/models` listing, which says what is in memory rather than what is on
  disk — and runs the loaded chat model, never an embedding model. Two loaded
  picks the lowest id so two calls in a row pick the same one. Nothing loaded
  skips the rung with "Local model skipped: nothing loaded in LM Studio".
  `TOWNREPORTER_QWEN_MODEL` still pins the rung to one exact model. Nothing in the
  app ever asks a local server for a model that is not loaded, and nothing loads
  or unloads one on the owner's behalf.

## Compatibility

No existing behaviour is removed and nothing else changes shape. This release
adds **one additive migration** — `0094_lead_kill_record.sql` — and **no new
scheduled task, service or program**. The migration adds four nullable columns to
`leads` (`kill_reason`, `kill_reason_url`, `killed_at`, `dup_kind`) and one
index; none has a default, so a lead handled before this release reads as "not
recorded" rather than as a decision nobody made. The nightly backup, the alerts
and the start of the 3100 copy ride on the five-minute watchdog the owner already
has, and `ops/start-stage.ps1` is a script, not a task.
