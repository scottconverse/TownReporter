## What changed

### Community resources (#409 to #412)

- **Phase 1 (#409).** The public page keeps each location's phone and hours with its own address. **Publish** also covers the schedules the service's location links point to, the organization's own phone and the phones of the linked locations. When the database cannot be read, `/registry` says the list could not be loaded and offers **Try again**.
- **Phase 2 (#410).** On `/desk/registry`, **Import a directory file** reads a JSON file in the HSDS bundle shape (8 MB at most), with a **Preview** that saves nothing. An import never publishes and never overwrites a stored row; a difference becomes a pending proposal. **All details** edits the service, the organization, contacts, places, hours, who can use the service, required documents, languages and accessibility. **Remove** marks a row removed and **Restore** brings it back; nothing is deleted.
- **Phase 3 (#411).** Each waiting change has **Accept and apply**, **Accept without applying** and **Reject**, each with an optional note. **Verification** records a check (how, what, an optional source link) with a snapshot of the entry's key facts. **Changed since verified** and **Needs checking** show what to re-check. Saving or publishing an entry no longer stamps it as verified; only a recorded check does. On `/registry` a check reads `Verified <date> (by phone)`.
- **Phase 4 (#412).** `/registry` has **Search**, **Category** and **Language** filters and 25 services to a page. Each service has its own page at `/registry/<id>`, a **Something wrong here?** link that opens **Corrections**, and a place in the sitemap. A read-only JSON API, version 1, is at `/api/registry/v1` with no sign-in. On `/desk/registry`, **Download directory file** saves one directory as the JSON file the import reads. See [docs/navigator/registry-api.md](../navigator/registry-api.md) and [docs/navigator/hsds-import.md](../navigator/hsds-import.md).

### Desk and Drafts

- **Leads that score 14 or more are drafted automatically (#400, #405, #406).** After a scan, a lead that scores 14 or more is drafted, whether it is new or held, through the same path as the **Draft** button with the model on Automatic. A lead whose draft the editor stopped is not drafted again. A lead the scan linked as a possible repeat of a published or killed lead is skipped.
- **Bulk publish and kill (#401).** Each row on Drafts has a tick box, with **Select all shown**, **Publish N selected** and **Kill N selected**. After a bulk kill, **Undo** puts every story back.
- **Publish is one press (#402).** **Publish all drafts** and **Publish N selected** publish with no confirm box; a hard refusal still stops that story and names it in **Not published**. The Queue and Drafts counts in the desk menu refresh every 15 seconds (every 5 seconds during a scan).
- **Publish all drafts also takes drafts that need you (#399).** It shows when the desk holds only **Needs you** drafts with a finished body.
- **Start N stories drafts every ticked lead (#407).** The batch has no five-lead limit, and ticked leads that are off screen are drafted too. The bar says how many are off screen.
- **Drafts no longer lock the job list for a long time (#408).** Evidence chunks are written after the job's lock is released, in batches of 200.

### Speed and front page

- **The Queue loads faster (#398).** The **≈ Printed** check works out each headline's words once, not once for each pair. No rule changed.
- **The meaning-search fill reads a window of rows per pass (#403, #408).** It no longer reads the whole evidence table every minute; a pass takes 2,000 rows.
- **Around the region (#404).** With no area button pressed, the front page shows the 6 newest published stories from outside the home town.
