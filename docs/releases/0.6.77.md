This release is **the redesign's dialogs reaching the screens — Today, the
Queue and the nav — and the drawn Kill dialog replacing the last plain status
write, with the mount work merged onto everything 0.6.76 shipped.**

## The dialogs reach Today, the Queue and the nav (units BN, BN2)

Phase 4 had built nine dialogs and mounted none of them; phase 6 had built the
AI follow-up rail and mounted none of it either. This work wires them in.

Today's **+ Add a lead** stops being a link to the Queue's legacy `#file-lead`
form and opens the drawn **Add a lead** dialog in place — a link or a tip, why
it might matter, and the **Then** choice. That legacy form still exists at
`/desk/queue#file-lead` and still opens where it did; eleven fixtures and
walks build their setup through that exact hash. Today's **+ New story N**
now opens the same drawn **New story** dialog the nav's **+ New** opens, and
the nav's own **+ New** — on the phone top bar and, newly, at the top of the
left rail above **Today** — opens it from any desk screen instead of
navigating to Today's composer.

**Hold H** on a Today row, and **Hold with a reason** in a Queue row's **More
▾**, both open **Hold this lead**: a reason the desk learns from, or **Hold,
no reason**. The row leaves the open list without a reload, because `holdLead`
now invalidates the `["leads"]` query the dialog reads from.

The Queue row's **More ▾** gains **Hold with a reason**, **Send to Dark
Desk**, **Start an AI follow-up** and **Kill with a reason**, alongside the
menu's existing **Open**, **Delete** and draft controls, in the drawing's
order. **Send to Dark Desk** opens the file and puts the editor on it. A
row's `more` prop is now four named slots the calling screen owns, rather
than a caller-supplied list, because the drawn menu puts **Merge with a
printed story** between two rows a caller could not otherwise reach into; a
screen that passes none of the four still renders the row as before.

The **Follow-ups rail** on Today, previously drawn but empty, now lists what
the AI follow-ups have actually found: the question in the editor's own
words, the finding sentence, the linked story and **Review finding** — or, if
nothing has been found, a sentence saying so instead of a blank panel.

**A row's `More ▾` panel no longer clips at the bottom of its own list.** The
menu used to open only downward inside a list with `overflow: hidden`, so the
last row's panel painted past the list's edge and could not be pressed
(measured at 1280×900 on a six-lead list: the last row's panel hit **0 of
7**). The menu now hangs upward when there isn't room below, and the four
lists that clip — the Queue's leads, the published list, the scan history
and the sources section — stop clipping while one of their menus is open;
the same six-lead measurement now reads **7 of 7** for every row.

Two things the drawing shows that are deliberately not built here: **Edit the
lead**, because nothing in this app edits a lead, so a menu row that only
said so is left out rather than half-wired; and **Merge with a printed
story**, whose press stays the desk's own duplicate resolution
(`resolveLeadDuplicate`) rather than a new merge behavior, because the button
keeps the word the press actually does.

No migration, no new server function, no model called.

## The drawn Kill dialog, merged onto 0.6.76 (unit BW)

The BN/BN2 mount work above was built against an older tree; by the time it
was ready, 0.6.76 had shipped phases 2a and 2b to main. This unit merges the
two branches — every mount BN/BN2 built and everything 0.6.76 shipped are now
both present — and spends the one `TODO(BN2)` marker the redesign had left
behind: **Kill** was still writing the lead's status outright instead of
opening a dialog.

**Kill X** on a Today row, the **X** key, and the Queue row menu's **Kill
with a reason** now all open the same drawn **Kill this lead** dialog: four
quick fills (**Not news**, **Already printed**, **Outside our area**, **Bad
source or unreadable**), a reason in your own words, and a link. **Kill with
this reason** is refused while the reason box is empty; **Kill, no reason**
always works, and **Cancel** keeps the lead and keeps what was typed. It is
the same `KillDialog` component the story page has mounted since phase 2b,
mounted once per page and re-pointed at whichever row was pressed. On Today
the row still shows **Killed** with its **Undo U** afterward, same as before;
Undo stays on the row rather than moving into the dialog, and the dialog does
not advertise a keyboard shortcut for an action it doesn't perform. The
reason now lands in the fields `setLeadStatus` already keeps (`kill_reason`,
`kill_reason_url`, migration 0094) — the same record the Queue's **Kill as
duplicate** has always written to — so a kill from a Today row no longer
loses its reason.

The merge (`git merge origin/main`, base `45b8d3ed`) had three conflicting
files, all resolved as unions rather than a pick of one side: `editor-dialog-
forms.ts` keeps both the mount work's `darkFilePrefill`/`darkFileSeed` and
main's `darkFileFromSeed`, since they are two different callers of the same
dialog; `editor-dialogs.tsx`'s `DarkFileDialog` now accepts both `prefill`
and `seed`, with `seed` winning when a caller passes both, and the reseed
factory memoized so an inline object literal can't hand it a new one every
render; and `dark-file.test.ts` keeps both suites. A stray import the union
resolution left unused was dropped afterward.

No migration, no new server function, no model called.

## What a reader sees

Nothing. Every change in this release is on the signed-in editor desk —
dialogs, a rail and a menu the public paper never renders.

## Migrations

**None.** `git diff 45b8d3ed..HEAD --stat -- migrations` shows no output —
nothing under `migrations/` changed since the 0.6.76 merge. The ledger stays
at `0104_draft_batch_dismissed.sql`.

## Compatibility

No existing action is removed or changed in what it does; this release wires
already-built dialogs into screens that used inline forms or plain status
writes for the same actions, and merges two branches without dropping either
side's work. Nothing changes shape at the data layer: no migration, no new
column, no new route.

## Limits

The dialog-mount and Kill-dialog work was each measured in a browser against
a throwaway in-memory desk, at the widths and states each unit's own report
names — not a full walk of every desk screen at every width. The row-menu
clipping fix was measured on one six-lead list at one viewport size. No
model was loaded or called to build or check this release.
