## What changed

### Custom scan source selection

The Scan page now offers a **Custom sources** scope beside General Scan and Section scan. An editor searches accepted sources by name or URL, filters by kind and tier, selects any number with a live count, and runs a scan against exactly that set. Proposed, rejected, and unavailable sources are never selectable, and unselected sources are never fetched. The selected accepted source IDs are persisted into the run snapshot before any fetch begins, so a run is reproducible even if the source list changes while it runs. Custom scope is mutually exclusive with a section scope.

### Saved source packs

Named, reusable sets of accepted sources can be created, run, edited, renamed, and deleted. A pack scan resolves the pack's **current** accepted membership at run time: editing a pack never rewrites a run that already started, and a source that later stops being accepted drops out of the pack automatically. Source membership is stored in `scan_source_pack_members`, and the pack itself in `scan_source_packs` (migration `0066_scan_source_packs.sql`). A pack scan does not edit section configuration.

### Truthful coverage accounting

Every scan run records the full path from selection to filing: `sources_selected`, `sources_attempted`, `sources_fetched`, `sources_failed`, `sources_analyzed`, `model_batches_used`, `model_batches_failed`, and the `failed_sources` set (migration `0065_scan_coverage_accounting.sql`). A zero-lead success, a provider failure, and a partially-analyzed run now render differently, and the editor can see which sources failed rather than only a count.

### Bounded batch analysis

The scan previously built one payload against a 48,000-character budget and stopped at the first source that would overflow it, so sources past the budget were fetched and paid for but never analyzed. Analysis is now split into bounded batches, each with its own model call. A 100-source scan is no longer silently truncated, a failed batch does not discard the successful batches' leads, and leads are de-duplicated across batches with per-lead source attribution preserved. Resume-from-checkpoint is not part of this release.

### Real scan-history paging

`listScans` now returns rows and a true total in one response, and the Scan page pages history with a real offset and a bounded page size. The panel shows "Showing latest N of M", and Show more appends older rows and disappears when there is nothing older to load. This fixes a defect where the previous growing-window request relied on the server returning more than its 50-row page clamp, so history could never advance past row 50.

### Section source counts and bulk assignment

The Sections panel now shows the accepted-source count per section and a visible warning when a section has zero accepted sources, and offers manual bulk controls — Assign all accepted, Clear section, and Copy from other sections. Assignment stays manual; there is no automatic assignment. A section scan with no accepted assigned sources continues to refuse with an explanation rather than running empty.

## Migrations

Two additive migrations are included in this release. Both were applied to the production database during the v0.6.54 deploy (production migration ledger: `0065_scan_coverage_accounting.sql` and `0066_scan_source_packs.sql`, applied 2026-09-19 00:14:38 America/Denver). They are recorded here as shipped and applied:

- `migrations/0065_scan_coverage_accounting.sql` — adds the `scan_runs` coverage count columns as `not null default 0`, plus the optional `failed_sources` detail column.
- `migrations/0066_scan_source_packs.sql` — adds `scan_source_packs` and `scan_source_pack_members` with cascade deletes, `unique (newsroom_id, name)`, and supporting indexes.
