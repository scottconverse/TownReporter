# TownReporter 0.6.51

**Date:** 2026-09-16  
**State:** Released.  

This is the documentation record for 0.6.51. It does **not** assert GitHub publication, a release ZIP, a fresh GitHub Actions result, production deployment, paid or subscription-model run, or live editorial acceptance.

## What changed

### Model selection, effort, and recovery

The model picker now carries an effort setting alongside the named runtime. Codex and Claude show only effort values accepted by that runtime; the request saves the selected value and refuses an unsupported value rather than quietly choosing another depth.

The editor's named runtime or Automatic remains the first explicit choice. A technical failure — unavailable service, expired sign-in, quota, timeout, network error, or no output — can move only the unfinished call to the next ready runtime. The job records the requested and actual model and effort; completed searches, reads, and document chunks are not replayed. A content/provider refusal is terminal. It does not trigger another provider call and never becomes a publishable draft. Unattended order uses Codex first and Claude Sonnet last; Opus runs only when an editor explicitly selects it.

Completed Queue batches now expose **Redraft**. Select a different available runtime and create a fresh reviewable draft; the batch flow still does not publish.

### Scheduled scans

Owners can edit the Daily scan from Server: local time, named model/runtime, that runtime's supported effort, a source cap from 1 to 12, and the accepted sources included in the schedule. The schedule remains disabled until the owner enables it, files leads only, and never publishes. Its UI explains the technical-failure recovery and terminal-refusal boundary before an owner saves the policy.

### Gemini and Grok connections

Adding a Gemini/OpenAI-compatible connection supplies the normal Gemini model default and validates the required key and model state before advertising the connection as ready. Migration 0061 preserves the encrypted key on an existing Google OpenAI-compatible connection and fills `gemini-2.5-flash` only when its model was blank. Saving, updating, enabling, or deleting a connection refreshes the picker state.

SuperGrok device authorization opens a blank popup during the click gesture, then redirects it when the xAI device URL is returned. If a popup is blocked or closed, the page shows a direct authorization link. The editor must still approve the code in their own xAI account; this release record does not assert a completed production OAuth connection.

### Documents and OCR

Direct Story and Opinion uploads retain and read all extractable PDF pages through the shared document reader, subject to the 20-million-character document-text limit. Generic capture and Dark Desk image-PDF OCR still limit each provider call to 12 rendered pages, but **Read entire PDF** now counts the retained original and processes all missing pages as durable batches. Each batch is saved before the next begins; a retry skips saved page chunks, and the editor sees batch/page progress plus an exact unread-page list. One click has a shared cooperative 10-minute and 48-transcription-attempt ceiling, then pauses safely for a later resume. A scan with no usable text layer can use page-only vision transcription. Upload or job completion does not certify OCR accuracy, and failed or oversized individual pages remain incomplete until successfully retried.

### Health and Windows lifecycle

The Server work-queue tile now separates active queued/running work and the latest terminal status by workflow kind from retained failed-job history. Historical failures remain visible without making an otherwise idle queue permanently read as a current failure.

The released `0.6.50` Windows packaged-install job failed because recursive shutdown followed an app-child relation to `csrss` and attempted to terminate that protected system process. The candidate excludes protected system names/PIDs, verifies creation time and parent-to-child ordering, and kills through a creation-time-verified handle rather than a bare PID. If the recorded root has already crashed, detached provider/browser descendants may remain: their ownership cannot be safely proved from a stale parent relation without a persistent supervisor. This boundary remains open.
