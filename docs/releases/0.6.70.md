This release is **four things the desk was asked for by the person using it**.
The owner posted his first real correction on 2026-09-25 and came back with two
complaints: *"the correction box starts empty"* — he expected suggested wording —
and a correction here is a public note above a story whose printed words cannot
be changed, while many newsrooms fix the text **and** append the note. The rule
for YouTube was already stated — *"use the API, not scraping"* — and had not been
built. The source list only ever grew by a person reading pages one at a time;
on the morning of 2026-09-24 production held **201 accepted sources, 175 waiting
suggestions and 6 rejected**, with nothing on the desk built to review 175 of
anything. And a news draft was never measured before it printed.

## The correction box does not start empty

Opening a correction now shows two short lines above the note — **What was
wrong** and **What is right** — and two buttons that fill the box from them. The
fact goes in the two lines (*the fee was $4,200* / *the fee is $2,400*); the
sentence is what the desk is for.

- **Suggest wording** asks the story model, through the same Automatic provider
  ladder every other call site uses, for one correction note in the paper's
  voice, built only from those two lines and the story it can see, and forbidden
  to add a fact of its own. The answer is read back with the same care as a
  headline suggestion: a fenced block, a "Correction:" label, quotes, a lead-in
  sentence and anything after the first line come off, and a list of options, a
  fragment, or a paragraph longer than the schema allows is refused rather than
  offered. The note goes **into the box**, not onto the paper, and nothing posts
  until the editor presses **Publish correction**.
- **Use a plain note** writes *An earlier version of this story said … In fact,
  …* on the desk, with no model and no network call. It is a second button on
  purpose: one button cannot both "leave the box exactly as you left it when the
  model is unreachable" and "fill the box with no model at all".

Every press says what happened — **Suggesting…** or **Writing…** while it works,
*Suggested below. Read it, change any of it, then post it.*, *Plain note written
from your two lines…* on success, and, when the model cannot be reached, *"The
story model could not be reached just now, so no wording was suggested. Your box
is exactly as you left it."* — with the box genuinely unchanged. Both buttons
need both lines, because a note built from half a fact reads finished and says
nothing.

## The printed text can be changed, with its note

**Also fix the story text** is a second checkbox in the same form, **off unless
the editor turns it on** — the default stays exactly the old behaviour,
note-only. On, it opens the printed body in an editor that already holds the
story as it printed, so the editor changes the words they can see. One press of
**Publish correction** then does both halves in **one transaction**: the note is
published, the body is updated, and the old body is written to a new append-only
table, `article_body_history`, with who, when and the correction that justified
it. The desk cannot reach a state where the text changed without its note, or the
note without the change it promises.

The slug never moves, so no link breaks. A fix that is unchanged — including
whitespace-only differences — or blank is refused in a sentence an editor can act
on, and a refused press writes neither half: no note, no text change, no history
row. The rules live in a module with no database in it, so they are tested
directly.

## YouTube is read through Google's own service

The desk learned about a channel's videos by scraping the channel tab HTML,
reading the public `videos.xml` feed and — last resort — listing the channel with
yt-dlp. All three are unofficial and move when YouTube reshapes a page. The
documented YouTube Data API v3 is now the first choice, and those three become
the fallback.

- **The key lives in the desk, write-only.** **Server → YouTube** is a new
  settings panel beside the other newsroom connections: one password-style box
  with **Save key**, **Test** and **Remove**, the line *A key is saved.* or *No
  key.*, and *YouTube units used today: N of 10,000*. The key is encrypted with
  the same helper the custom AI connections already use, under the installation's
  authentication secret. It is **write-only**: no screen can re-display it.
  `YOUTUBE_API_KEY` in the app environment overrides a saved key. Saving a new
  key also clears any recorded quota refusal, so last week's refusal cannot keep
  the desk on the feed after the key was replaced.
- **Discovery costs at most three calls, one unit each.** A channel by id, by
  handle or by username; its newest 50 uploads from the uploads playlist;
  then the details for those videos — title, description, published, duration,
  and whether a video is upcoming, live, ended or an ordinary recording. Google's
  "Deleted video" and "Private video" placeholders are dropped. **`search.list`
  is not called anywhere**: it costs 100 units a call against a 10,000-unit day
  and those three answer every question the desk asks. Capture readiness now asks
  the same service first and falls through to the player page and yt-dlp when
  Google says it does not know yet.
- **The key is never in a URL.** It travels in a request header, so it cannot
  appear in a printed request, a redirect chain, a log line, or the text of an
  error — including an error Google itself writes.
- **No key, a bad key, a dead network, a spent allowance — all fall back.** The
  channel tab, the public feed and the yt-dlp listing run unchanged, and the scan
  receipt and the meeting-capture coverage line say which path produced the
  listing — *Read YouTube with the official API.* or *… Read the public feed
  instead.* — so a thin listing is never left implying that Google answered.
  **Quota is terminal for the Pacific day**: a refusal is recorded against
  today's Pacific date and the desk answers from the feed without calling Google
  again that day. The day rolls over on Google's reset, not on a timer. Pressing
  **Test** always asks Google, even on a refused day, because a person pressing
  it is asking a direct question and gets the refusal as its answer; that one
  call is counted like any other.
- **Transcripts and media are unchanged.** yt-dlp and the caption tools still
  fetch captions and audio. The API cannot download captions for videos this desk
  does not own, so only the listing and the readiness question moved.

## Suggested sources can be cleared

The scan's reply has carried suggested sources since the daily scan was written,
and the desk has stored them ever since — with a URL and a title and nothing
else, so the only way to decide one was to open the page. The research pass and
the Dark Desk, which read the most new pages of anyone, filed no suggestions at
all, and nothing on the desk was built to clear a backlog.

- **Why and where are recorded now.** **One** new set of columns on `sources`
  holds the model's one sentence about what the page offers the paper, who
  suggested it — **the scan**, **the research pass**, **the Dark Desk** or an
  editor — the scan run or lead it came from, the section the model guessed, and
  who reviewed it and when, with an optional note. A suggestion is a source row
  at an earlier status, not a second table. Every row that predates this release
  is empty in all of them, and the desk says so in words: *No reason was recorded
  when this was suggested*, and `not recorded` where the suggester is named. An
  empty value is "not recorded", not "no reason".
- **The scan now asks for a reason and a section**, and both are optional in the
  reply, so a reply written before this release still parses as a suggestion with
  no reason and no guess. The section guess is kept only when it names a section
  the run actually accepts, because the review screen preselects the section
  picker with it and a key no section has would preselect nothing while looking
  like a decision.
- **One door for three passes**, holding the rules each caller would otherwise
  have to remember. **A page, not a URL string**: the same page written with
  `http://`, `https://` or `www.` is one page here — and a page this newsroom
  already has, at any status, is not proposed again. **A results page is not a
  page**: search engines and any host's search endpoint are refused, while a
  homepage or a section front is not — an agenda index is exactly what the owner
  wants watched. **A social profile only for a paper that watches social
  sources**, read from the one place that decides what counts as a social source;
  the Longmont edition ships with two city accounts on watch, so a scan finding a
  city account proposes what the owner asked it to watch. "Watches" means
  **accepted** — a dropped row is not a standing decision, and a suggestion
  already waiting is not one either. **Nothing a pass did not read**: the research
  pass proposes what it opened and cited, and the Dark Desk proposes the pages it
  read while developing a file, capped at twelve, each with a reason naming the
  file.
- **A screen that can clear 175.** The **Sources** page's third group is now
  **Suggested sources: N** — newest first, so the run that just finished is at
  the top. Each row carries the reason, the suggester and its lead, and the
  section guess, which starts the section picker. **Anyone / The scan / The
  research pass / The Dark Desk / Not recorded** filter the list. Per row:
  **Accept to \<section\>**, **Reject**, and an optional note saved with either.
  For a batch: **Select \<title\>** on each row or **Select all N**, then **Accept
  selected** or **Reject selected**, with one section picker for the batch. Every
  press reports itself — **Saving…**, then *Accepted 3 suggestions and filed them
  under Council*, or **Nothing was changed:** and why. A batch is **one
  transaction**: status, review stamp, note, section link and the section
  revision all commit together or not at all, so the screen can say nothing was
  changed and be telling the truth. A row sent back to waiting clears its review
  stamp rather than leaving a reviewed-at on a row waiting to be reviewed. The
  section half stays **owner-only**, and an editor who is not the owner sees the
  guess as a note rather than as a picker they cannot use.

## A style check on a news draft

A news draft is now measured by code, and the model is asked to repair only what
the code found. Code measures first; the model rewrites second; code measures
again. A model never decides what counts as a fault.

- **What is measured**: unnamed attribution, importance-only sentences,
  participle tails, dressed-up verbs, filler words, synonym cycling, paste
  artifacts, tracking parameters and URL redirects, paragraphs over the form's
  cap, sentence-length variation, a missing short-next-to-long beat, and six-word
  repeats. The thresholds are named constants marked in the file as starting
  values rather than findings of fact — they were chosen by reading local-news
  sentences, not fitted to a corpus, and a real desk will want to move them.
- **Quoted text is never a finding.** Quotations are the source's words; the
  audit reads past them, and a repair is refused if it alters one.
- **The repair is bounded.** If anything needs fixing, **one** model call
  receives only the findings and returns the corrected body; the audit runs
  again. At most **two** rounds. A repair is rejected and the previous text kept
  when it flattens the sentence rhythm or changes any quotation, number, name or
  URL, and it may not add facts.
- **The story page shows a plain Style check list** — *"3 things to fix:"*, each
  finding's location, its sentence and the words it came from — with review
  findings under a fold. It reuses the existing panels, adds no layout, and
  blocks nothing. **Fix these with the model** runs one repair round on demand.
  Nothing auto-publishes; the editor may ignore every finding, and the result is
  saved as an ordinary draft revision with the desk saying so. A draft that still
  has something to fix gains the review reason `style-audit-open`. The findings
  are stored with the draft. **No new table was added** for this.
- The audit judges whether a draft *reads*, not whether it is true. Truthfulness
  is the evidence check's job and is unchanged. Opinion pieces have their own
  path and were not touched.

## What a reader sees

Only what they already saw, and one thing less surprising. A note-only
correction is exactly what it was: the note on the article page and on
`/corrections`. A correction that fixed the text shows the corrected story plus
the same note; the words the story used to carry are **not printed anywhere**,
which is the choice 0.6.67 already made for headline history. A suggestion is a
desk-only row — never fetched, never scanned, never published until an editor
accepts it, and accepting it only puts the source on the watch list for the next
scan. The YouTube change is invisible on the paper. Nothing in this release
touches the reading experience except the corrected text itself.

## Compatibility

No existing behaviour is removed and nothing else changes shape. This release
adds **three additive migrations** and **no new scheduled task, service or
program**.

- `0095_article_body_history.sql` creates the append-only table a corrected body
  is written to — old body, new body, who, when, and the correction that
  justified it — plus its article index.
- `0096_youtube_data_api.sql` creates two tables: one row per newsroom holding
  the encrypted key and the Pacific day Google last refused for quota, and units
  used per newsroom per Pacific day.
- `0097_suggested_source_origin.sql` adds seven nullable columns to `sources` for
  the reason, the suggester, the run, the lead, the section guess, the review
  stamp and the review note, plus a partial index over waiting suggestions, which
  is the review list's own query.

Every one of them is nullable or creates a table that did not exist; none has a
default and none rewrites an existing row, so everything that predates this
release reads as "not recorded" rather than as a decision nobody made. There is
no new background job, service or installer step, and no new port.

The packaged release note names `v0.6.70` and the expected asset files without
embedding its own commit or ZIP hash. The JSON metadata and `.sha256` sidecar
are the authorities for those values; GitHub is the authority for publication
state.
