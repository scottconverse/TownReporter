This release is the **Control page**: the terminal menu an operator opens on the
machine that runs the paper now has a page in front of it. The numbered menu is
still there, unchanged in what it can do, and is still the fallback.

## What the owner can do on the machine

The Desktop shortcut used to open a console with a numbered menu. It now opens
**TownReporter Control** at `http://127.0.0.1:3095` — a page on this computer,
served by this checkout, that says whether the machine is healthy and puts the
six menu actions behind buttons.

### One line, then one card per check

The top of the page is a single large line: **Everything is up**, or **N things
need attention**, where N counts only the checks that must be up. Under it each
check is one card carrying a plain verdict and, when it is down, the one button
that fixes it — so the page answers "what is wrong" and "what do I press" in the
same place. The rows are the database, the paper, the public site, the local
Redlib reader, Ollama, the last backup, the last scan, and the test copy.

A row that is down but does not matter is marked **optional** and never inflates
the count. Redlib and Ollama are the two that behave this way: the paper serves,
and the scan reads Reddit through the subreddit's own feed, whether or not either
is answering. That is the same distinction `ops/status.ps1` already draws with
its NOTE lines, carried onto the page rather than decided a second time.

### The buttons say what the menu says

Six actions, in the menu's own words, so the page and the console describe the
same action the same way:

| Button | Runs |
| --- | --- |
| Check | reads the status again |
| Restart the paper | the app's own restart, on this machine |
| Restart the tunnel | the Cloudflare connector, when the outside world cannot reach the paper |
| Start everything | Postgres, the paper, the reader, the tunnel |
| Stop everything | stops all of it — **asks first** |
| Restart the Reddit reader | `ops/redlib.ps1 restart`, when threads read as headlines only |

Pressing one streams the action's own output into a box on the page while it
runs, so a slow restart is visibly working rather than apparently hung, and the
status refreshes when it finishes. The buttons are disabled while something is
running, and the page says which action is running.

**Stop everything asks first.** It is the one action that takes the paper
offline, so it opens a dialog naming what it will stop, and cancelling closes it
and does nothing at all. The confirm button is labelled `Take it offline` so the
press that matters cannot be a reflex. The server refuses the same action
without the confirm word, so the dialog is not the only thing in front of it.

Nothing on this page publishes, deletes or edits anything. There is no button
for the desk, no button that touches an article, and no free-text field: the
page reports and restarts, and that is the whole vocabulary.

### The page also links to the three places an operator wants

The public paper, the editor desk, and the test copy on port 3100, as ordinary
links. The desk and the test copy are on this machine; the public site is the
real one.

### The numbered menu stays

`ops/TownReporter Control.cmd` is unchanged in its first six entries and gains a
seventh: **Open the Control page**. The menu remains the fallback for the case
the page is the thing that is broken — it is a `.cmd` that needs nothing but
Windows, while the page needs the checkout and Node. It says on its own screen
that nothing is started or stopped until a button is pressed.

The Desktop shortcut now runs the launcher through `ops/run-hidden.vbs`, so the
page opens without a console window behind it. `ops/install-shortcut.ps1` builds
that shortcut; its `-Fallback` switch builds the old console one instead. **No
new scheduled task is added** — this is a way to press the same buttons, not a
second thing that starts the paper.

### Dark by default, and readable

The page paints dark on the first frame, before anything else runs, and a Light
toggle in the corner is remembered across reloads in the operator's own browser
storage. Both palettes meet WCAG AA, no piece of text on the page is smaller
than 16 pixels, and every button and link is at least 44 pixels tall so it can be
hit with a thumb on a laptop with a touchscreen. The whole page is reachable by
keyboard, and a press shows a visible result within a frame.

A page that exists to say whether things are healthy must also render when the
paper is down, so it loads nothing from anywhere else: no font, no script, no
style sheet, no icon request that could 404. It is one inline document served by
the checkout it sits in.

## What changed for safety

- **It listens on loopback only.** The page binds `127.0.0.1`, so it is not
  reachable from the LAN, the tunnel, or the internet. That is necessary and not
  sufficient: every page the operator's browser has open can POST to loopback.
- **A Host header that is not this server is refused**, before the page — and
  before the token inside it — is served.
- **Every button press is checked against two things.** The page carries a token
  minted per run and read from a header only, and the request's Origin or
  Referer must be the page's own. A page on another origin cannot read the token
  and cannot forge either; a request with the token but a foreign Origin is
  refused, and so is one with no Origin at all. The token is never accepted from
  a query string, where it would end up in logs and history.
- **The action vocabulary is fixed and closed.** Each action is a fixed absolute
  System32 executable — `powershell.exe` or `schtasks.exe` by full path, never a
  PATH lookup — spawned with an argument **array** and no shell, so no request
  can add an argument or turn one into a second command. There is no endpoint
  that takes a command, a path, or a model name from the page.
- **An action id that is not in the table is a 404**, and the table is checked by
  own-property, so `/api/action/constructor` is a 404 rather than a call.
- **One action at a time.** A second press while something is running is refused
  with a 409 and the page says so, so two restarts cannot interleave.
- **It leaves by itself.** The page closes the server after an hour with no
  requests, so a shut tab does not leave a listener behind. An open tab polls
  every fifteen seconds and keeps it alive. It writes `ops/.control.pid` while it
  is up, and the launcher will not start a second copy.
- **Nothing is stopped by image name.** The Reddit reader is stopped through the
  pid file its own installation wrote, exactly as the rest of the machine's
  scripts already do.
- **Ollama is only asked, never loaded or unloaded.** The page reads whether a
  model is ready through `lms ps --json` and changes nothing about it, because a
  model may be mid-draft.

## Migrations

This change adds no migration and no scheduled task. The page is a reader and
six fixed actions over scripts that already exist; it stores nothing, and the
existing logon task and five-minute watchdog are untouched.

## Known limits

- **The browser walk presses a button, but not on the real machine.** The walk
  boots the page's server in-process with an injected runner that spawns
  nothing, on port 3505 rather than 3095, so the one button it presses cannot
  reach the paper, the tunnel or the reader. It asserts instead that the argv
  vector the button produced is an absolute System32 PowerShell running
  `ops/redlib.ps1 restart`, which makes the stub positive evidence about the
  button rather than a silence.
- **The real-machine proof for this release is read-only.** The page was started
  from the build checkout on 3095 and read once; no action button was pressed on
  the running paper while building it. Nothing here was run against a real AI
  model.
- **The last-backup row reads a path this build could not list.** The row reports
  the newest file in the backup directory (`C:\Users\scott\Desktop\Code\townreporter-backups`
  by default, overridable in the environment). Where that directory cannot be
  listed, the row fails soft and says so rather than reporting a healthy backup
  it did not see.
- **The last-scan row reads a record, not the desk.** It reports what the last
  scan wrote, through a small read-only helper. If that read fails it fails soft
  too — a status page that breaks when one row cannot be read is worse than the
  row.
- **The status is `ops/status.ps1 -Json`, one source of truth.** The page adds
  no check of its own beyond the version, the last backup, the last scan and the
  local model, so the console and the page cannot disagree about a row they both
  show.
- **The page is a convenience for the machine it runs on, not a remote console.**
  It is deliberately not reachable off loopback and deliberately has no
  authentication beyond that, because loopback plus the Host and token gates is
  the boundary it is built to.
- **Production deployment is not asserted here.** A repository version, a tag,
  or a GitHub release does not establish what the live paper is running.

## Evidence boundary

The source tree and a locally built candidate can prove implementation, tests,
migrations, browser behavior, and package contents. Only the GitHub release page
can prove publication, and only a separately authorized production verification
can prove deployment. This note does not turn one of those facts into another.
