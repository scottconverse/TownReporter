## What changed

This release carries accepted public-trust and security fixes. It is not a new
product surface: it changes what the paper refuses to do without a person, and
what the server hands to code it runs.

### Every published story says how it was made

A published article now carries the required disclosure sentence where a reader
can see it, and so does the reporting page. The sentence is a constant in the
source, not a per-story string, and it names what was used and where the records
are listed.

A second sentence covers the template-assembled routine notices (Today,
Weekend, Deadlines). Those are assembled from owner-approved public sources with
no model in the loop, so the reported-story sentence would have claimed that a
person reviewed and edited writing no person wrote. The two paths are told apart
from the publication record, not from the story's form, because the form is the
same on both; a roundup that was silently given no disclosure at all is now
distinguishable from a considered omission.

### A draft's section is confirmed before the story prints

The section a story files under is now an explicit editor decision rather than a
value that publication reads back. The desk shows a confirm action that saves
the draft first, and publication is refused when the section or the body has
changed since that confirmation. The confirmation is recorded against the
draft's evidence review, so the record shows which draft state the editor
confirmed.

The topic chooser itself is unchanged. What is new is that its output has to be
confirmed by a person before it reaches print.

### Italics render in story bodies

`*italic*` and `_italic_` now render as italics. Bold text, bullet lists and
arithmetic such as `5 * 3` are unaffected, and the tests covering them passed
before and after the change.

### A named outlet the Sources do not cover refuses publication

Printing is refused when the body names an outlet on a fixed named-outlet list
that the story's Sources do not cover, whether the outlet is credited by URL on
its own domain or by a source title. The check runs at publication, is shown on
the desk, and never appears on the public page.

An editor can override one outlet at a time for one draft. Each override records
who granted it and when, and the recording is append-only in
`migrations/0086_named_outlet_overrides.sql`, alongside the meeting review
history the same pattern came from. An outlet overridden once stays overridden
for that draft; any other outlet a later rewrite names still blocks.

The list is a constant in the source, not a table, and it can match a phrase
rather than a masthead: the words "times call" in ordinary prose can match
"Times-Call". That is a known limit below, not a defect found in testing.

### The development operations page no longer crashes

The development `/desk/ops` route crashed because its static import closure
reached fifteen `node:` builtins across seven modules — filesystem and path
helpers pulled in by engine code that the route did not need. Those helpers now
live in a server-only module and the engine imports are resolved inside the
handlers.

The built-server smoke walk now opens `/desk/ops` and asserts in the browser that
the error boundary did not render. The walk previously accepted a 200, which was
never enough: this crash was one of the failures that shipped a 200 response.

### Spawned provider CLIs get a named environment

Provider command-line tools are no longer started with a copy of the server's
environment. A child receives a named allow-list of variables, so a credential
belongs to the child that needs it — the Anthropic key reaches the Claude child
and nothing else does. The sign-in path that spawns both CLIs was rewired to the
same allow-list.

Two child processes still inherit the full environment, and that is a known
limit below rather than an oversight.

### The URL guard reads the transition and translation ranges

The address guard blocked the literal private and reserved ranges but not the
ranges that carry an embedded IPv4 address. Requests to those are now refused:
`198.18.0.0/15`, `192.0.0.0/24`, `64:ff9b::/96`, `64:ff9b:1::/48` and
`2002::/16`, with `::ffff:0:0/96` under test as well. Each case is asserted in
both directions, so a blocked address stays blocked and an ordinary public
address is still fetched.

### Grok federation is opt-in

An install no longer federates to the Grok broker unless it asked to. The
preview client that was committed is still present but is reachable only when
`TOWNREPORTER_GROK_PREVIEW=1` is set; an explicit `GROK_AUTH_*` configuration
always wins over it, a half-configured client is treated as no client, and no
provider is registered when the decision is null.

Email sign-in is unaffected. The authentication switch is unchanged, and turning
Grok off does not turn sign-in off.

### The four surfaces that take input check its shape

Requests are validated on publication, on authentication and sign-in and
sign-up, on paper settings, and on provider and model connections. A validator
that returns its argument unchanged is a type annotation, not a runtime check,
and those are what this replaces.

Two genuinely unbounded writes were found in the sweep and bounded: the first-run
setup form and a local model's base URL and identifier. An authentication body
is capped by its content length and refused with 413 rather than buffered first.

A full sweep of every input path is not in this release. It is scheduled for
0.6.63.

### The first owner is claimed in one transaction

The first owner on a fresh public install is now claimed by one transaction that
locks the newsroom row, re-checks, and inserts. The one-owner index is created
and verified, and a desk whose index is not verified refuses to start rather than
trusting the re-check on its own.

There is still no setup code for the first owner. The first visitor to a fresh
public install becomes the owner, and whether that should change is an open
decision.

## Operator notes

1. **Tell editors about the section confirmation before the next publish.** On
   every unpublished draft, an editor must confirm the section once before the
   story can print. A draft that was written before this release has no
   confirmation recorded, so it will refuse until someone confirms it.
2. **Two live stories need their section corrected.** Both currently file under
   a section that is not the one they should print in.
3. **HSTS is set in Cloudflare, not in this repository.** Cloudflare → SSL/TLS →
   Edge Certificates → HSTS: six months, Preload off, and Include subdomains only
   if every subdomain is served over HTTPS. Nothing in this release enforces it
   from the application.
4. **A server that relied on the built-in Grok preview client must now ask for
   it.** Set the install's own `GROK_AUTH_*`, or set
   `TOWNREPORTER_GROK_PREVIEW=1` to keep the preview client. An install that does
   neither will find no Grok provider.

## Known limits

- **No setup code for the first owner.** The first visitor to a fresh public
  install still becomes the owner. The decision is pending.
- **The named-outlet list is a constant**, edited in the source rather than in
  the database, and it is not exhaustive.
- **"Times-Call" can match the words "times call"** in ordinary prose, which
  refuses a story that should have printed. The editor's override is the way
  through.
- **Two child processes still inherit the full environment**: the `yt-dlp` and
  Python invocations at their three call sites keep the previous behavior.
- **The topic chooser itself is unchanged.** The general-scan fallback and the
  keyword order in `topicFromText` are as they were; the editor's confirmation,
  not the chooser, is what guards the section.
- **The input-check sweep is scoped**, not exhaustive. Some validators were
  deliberately left as they are. A full sweep is 0.6.63.
