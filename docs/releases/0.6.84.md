## What changed

### One model picker, and the models Automatic uses

Every screen where an AI does work now shows the same model picker with the full list: Automatic, every available Codex, Claude and Gemini model, Local models (with a second picker of the models the computer has found, defaulting to the one that is loaded), and saved custom connections. The model saved for a job is the model that runs.

**Automatic** tries four models in this order and uses the first that is ready:

1. DeepSeek v4.1 Flash 1017 (`deepseek-v4.1-flash:1017-cloud`), run inside the Claude Code CLI with thinking effort set to none
2. Local model, whichever model the computer has loaded
3. Codex Sol 6.1 (balanced)
4. Claude Sonnet 5.5

Gemini is not on that ladder. Gemini 3.8 Flash and Gemini 3.1 Pro stay models an editor can pick by name. Opinion's Automatic is DeepSeek v4.1 Flash 1017, then Codex Sol 6.1, then Claude Sonnet 5.5. A named pick is the first choice; if it hits a usage limit or a technical failure, only the unfinished call moves to the next ready model, every hop is recorded, and a provider refusal stops the run. The Story page names the writer while a draft runs and afterward shows "Last draft: <model>, <time>".

A normal news lead is now written by the report-local-news skill when the pick is DeepSeek or a Claude model. If the skill cannot finish, the same model writes the story the usual way and the story page says so.

### Warn, never block

Where the desk used to refuse, it now warns and lets the editor go on. Every warning has an "anyway" button: **Publish anyway in <section>**, **Kill anyway**, **Hold anyway**, **Draft anyway**, **Add to this story anyway**. Each override is written to the audit trail with the editor, the time, the warning and the target. Things that are truly impossible stay impossible.

### Find evidence and search by meaning (editor desk only)

On the Story page, under **Your source material**, **Find evidence** searches by exact words and by **Close in meaning**. A third list, **Our past stories close in meaning**, shows earlier published stories and the files added with **Add documents**. The writer is given the five closest past stories as background only. If the meaning model is unavailable, the exact-words list still works and a plain line says so. None of this is on the public paper, and the public search box is unchanged. `TOWNREPORTER_MEANING_SEARCH=off` turns the background index off.

### Routine editions

**Today in town** now prints a time-ordered list of the day's events from approved public calendars, grouped under Morning, Afternoon and Evening when there are six or more. Every eligible routine notice keeps a saved status (deferred, in review, published), and each run says plainly why items need review. The three automatic editions are Today in town, This weekend and Deadlines approaching. Ordinary stories still reach the paper only after a person reviews them and presses Publish.

### Operations

Backups keep three days on D: and nothing on C: once a copy is verified. The watchdog leaves a start alone for 600 seconds and probes twice before it repairs anything. `ops\promote.ps1` hashes the lockfile by full path. The server answers 503 until the database is current. Twenty-seven migrations (0129 to 0158) are added; all are additive.

## Limits and review boundary

- Drafts are AI-assisted. Models invent facts, misattribute quotes and mangle names, especially from auto-captions. The checks narrow what an editor must read; they do not replace editorial verification.
- Ordinary editorial review remains required. Editors must inspect the cited packet, minutes, recording or other primary material for consequential claims.
- Search by meaning finds earlier stories and files of the same paper. It is a pointer, not evidence, and nothing it finds is added to a story's text.
- A fresh-machine human acceptance of the installer is not documented here, and this note does not claim that a Setup.exe was attached to the release.
