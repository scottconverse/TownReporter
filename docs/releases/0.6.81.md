This release answers a caching fault a reviewer could see from outside, and
closes the drawn-desk work: the front page's lead gap, one row per event in
"This week", a meeting story's transcript readable in full, the story
workbench and the Server screen as drawn, Today and its rail at laptop widths,
long lists at 25 rows, every reason Publish is off stated in words, an honest
light theme for Dark Desk, the first-owner setup code and recovery codes
returned with the review's three problems fixed, and the manual follow-up
workflow retired without deleting a row. Two additive migrations. No
production deployment and no live-model run is asserted by this note.

## Caching: a release can no longer be outlived by its own bytes

- **Every HTML page now carries a cache instruction saying how long it stays
  good.** A reviewer saw townreporter.org pages from 0.6.68 and 0.6.76 after
  0.6.80 had shipped: the pages were new, the bytes a browser, a proxy or
  Cloudflare handed over were not. The rule lives with the other security
  headers in the one place that already sets a header on every route, and is
  gated the way the app already decides what a document is — on the response's
  own content type. The desk tree (`/desk` and everything under it) answers
  `private, no-store`; every other document answers `no-cache`, which is
  "revalidate before you use it", so a cache still serves a fast 304 when
  nothing changed and the new page the moment anything did
  (`server/middleware/security-headers.ts`).
- **The hashed bundles under `/assets` are deliberately untouched**, because
  their names change when their bytes change, so their long cache is correct
  and is what keeps the paper quick. So are the feed, the sitemap, images and
  every server-function JSON reply. `scripts/security-headers-e2e.mjs` now
  asserts all four properties on a built server: `/` and one article
  revalidate, `/desk` is not kept by any cache, and a real bundle keeps
  `public, max-age=31536000, immutable`.

## Dark Desk: the light theme is honest

- **One region ignored light, and it was not the theme tokens.** The captured
  page panel under the rail imports the public reader's stylesheet globally,
  and that stylesheet declares the reader's light palette **on the panel
  element itself** — an on-element declaration no inherited value can outrank
  — while the panel's desk-scoped rules kept painting from the desk's tokens.
  In dark that is `--adeep`/`--mut` text on the reader's cream ground: 1.23:1
  and 1.9:1. The fix re-points the reader's ten names on the panel but resolves
  the values **on the shell** under `--desk-page-*` bridges: resolving on the
  panel would be a same-element `var()` cycle against the reader stylesheet and
  compute to the guaranteed-invalid value, which takes all three panel borders
  down with it, measured and kept as a control
  (`reports/CQ-dark-desk-light.md`, `src/desk-astra.css:2088-2110`).
- **Measured with the same instrument before and after**, over 342 visible rows
  per theme: dark rows painting the reader's cream palette **34 → 0**, dark text
  rows under 4.5:1 **16 → 0**, theme-invariant text rows **8 → 0**, and light
  unchanged to the pixel — **0 of 5,568,000 px differing**. The rules read the
  same nine token names every other desk screen uses, the six hard-coded night
  literals that sat in an unreachable `[data-desk-page="dark"] .nightpanel` rule
  are gone, and a test now fails on any literal colour under
  `[data-desk-page="dark"]`.

## Follow-ups: the manual workflow is retired

- **The manual workflow is gone from every screen**: the `FollowUpItem` card
  (Record reply / Nudge / Drop), the Follow-ups screen's "Manual asks"
  section, Today's rail asks, and the story page's "People who still need to
  respond". The three screens now show AI agents only, in light, dark and at
  390px. The four manual server functions and their input schemas are removed
  rather than left refusing, and nothing calls them
  (`reports/CU-retire-manual-followups.md`).
- **No data was deleted.** `migrations/0106_retire_manual_follow_ups.sql` is
  additive: it marks open manual rows `dropped` and keeps every row and the
  table, so an archived row keeps its `who`, `what`, `due_on`, `reply_text` and
  story link. Replaying it is a no-op, which a new suite asserts directly.
- **Converting an old manual row into a `recheck` agent was not built**, and
  the report gives the reason: a non-search agent cannot be created without
  targets, every target must already be an `http(s)://` URL, and a manual row
  named its URL or document in prose, where nothing in this codebase parses
  it. Doing it would have meant inventing URLs, which is an editor's judgement
  call (`reports/CU-retire-manual-followups.md`).

## First-owner setup and owner access

- **The setup code and recovery codes are back**, and the review's three
  problems are fixed: an unclaimed owner with a session stays on the setup form
  with the error rather than being stranded by a mistyped code; redeeming a
  code burns it, sets the password and writes the audit row in **one
  transaction**, so a failed audit write can no longer lock the owner out; and
  the codes are **salted scrypt hashes**, not bare SHA-256, so a database copy
  cannot be cracked offline. Every CI walk that creates the first account fills
  the code through one shared helper reading the file the server writes in that
  job's data root — all 30 ran, exit 0, with 19 port-closure proofs
  (`reports/CR-setup-code-fixed.md`).

## Migrations

Both migrations are additive. Neither removes or renames a column, table or
index, and an install with no data affected keeps working unchanged.

- **`migrations/0106_retire_manual_follow_ups.sql`** marks every open manual
  follow-up row `dropped` — the predicate is `agent_kind is null`, "not an
  agent", because that rather than `who` or `due_on` is what distinguishes a
  manual ask. `dropped` was chosen over a new status because the existing check
  constraint already means "the editor put this down". Replaying it is a no-op.
- **`migrations/0107_owner_setup_and_recovery_codes.sql`** carries the
  first-owner setup code and the recovery codes returned by this release.

## Migration numbering

**`0102` was never used and does not exist.** `scripts/migration-plan.mjs`
sorts migration filenames with `localeCompare`, and `"0102_…"` sorts *before*
the already-applied `0103_read_hourly.sql`–`0105_lead_edit_record.sql`; using
0102 would therefore make the new migration apply out of order on any desk that
had already run 0.6.80. The directory holds no file numbered 0102 at any point
in its history. `0106` is the next free number after `0105`.

The two files this release adds, as `git diff --name-only origin/main --
migrations/` reports them:

- `migrations/0106_retire_manual_follow_ups.sql`
- `migrations/0107_owner_setup_and_recovery_codes.sql`

One numbering note worth recording, because two branches each claimed `0106`
and only the merge showed it. The 0.6.80 prep named its setup-code migration
`0106_owner_setup_and_recovery_codes.sql` (`62ce7cdb`); that unit was taken out
of 0.6.80 before it shipped (`42b41195`), so 0.6.80 carries only `0105`. The
setup-code branch later restored the file under the same number (`d09450f7`,
2026-09-27 23:46) while, on a branch that had not seen it, the follow-up
retirement claimed `0106` for itself (`dfa76fa4`, 2026-09-28 00:26). The two met
at the merge (`372ba70f`) with a genuine filename collision; the setup-code file
was renumbered `0107` so that `0106` stayed with the retirement and neither
branch's migration changed content.

## Operator notes

1. **The document cache rule needs no operator action**, but it is worth
   knowing that a desk page will now never be served from any cache. If you
   front this app with your own proxy, do not add a long cache for `/desk`.
2. **Two migrations apply at boot**, in file-name order, as usual. Both are
   additive; the manual follow-up rows are marked, not deleted, so a database
   reader still sees the history.
