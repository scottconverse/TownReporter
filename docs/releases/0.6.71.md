This release is **one screen the desk was already able to answer and did not**.
Choosing **Local model** listed every model on disk with nothing to say which of
them were in memory, and the word "loaded" appeared only in an option's hover
title. Discovery has always read LM Studio's `/api/v0/models` and Ollama's
`/api/ps`, so the load state was known and simply never reached the list. An
editor picking a model could not see which ones a run could actually use, and a
hand-picked model that was not in memory failed at the call instead of before it.
**No model was loaded, unloaded or called to write this release or to check it**:
every check ran against fake catalogs and fake servers.

## The list says what is loaded

A model in memory now reads `<id> · loaded`. The id still comes first, because
that is the part an editor is choosing between; the marker follows it. Inside
each server group the loaded models sort ahead of the rest, by id within each
group, so the models a run can use now are at the top of the list rather than
scattered through it.

The help line under the select answers the question in words for every state the
picker can be in: loaded now, not loaded, no load state reported, a cloud model,
which model **Use whatever is loaded** is currently pointing at, or which model a
run would fall back to.

## Use whatever is loaded

**Use whatever is loaded** is the first choice and, when nothing has been stored
and a local server reports a loaded non-embedding model, the new default. When
nothing is loaded the default is unchanged — the preferred cloud model, else the
catalog's own — and the help line says which model it is using and why.

- **It is stored as an ordinary pick, which is why it needs no migration.** The
  choice is written to the model-choice table the picker already writes, as a
  sentinel with `*` in both halves of `base_url` and `model_id`. Those columns are
  plain `text not null` with no value constraint, the save validator accepts any
  two non-empty strings, and a real pick always carries a server address, so the
  sentinel cannot collide with one. No column, table or index is added.
- **It resolves at call time, through the function that already existed.** The
  sentinel is resolved through the same function the Automatic rung already used
  — LM Studio before Ollama, in that order — so a model loaded after the picker
  rendered but before the run starts is picked up.
- **The receipt names the model that actually ran**, as the rung does:
  `Local model (halo-brain-35b)`. An editor reading the receipt can see which
  model answered rather than that "a local model" did.

## The desk never loads a model

A hand-picked, non-cloud model on a server that reports load state, when that
report says the model is not loaded, stops before the call:

> `<id>` is not loaded in LM Studio. Load it there, or pick Use whatever is
> loaded.

**Use whatever is loaded** with nothing loaded stops with its own sentence:

> Local model: nothing is loaded in LM Studio or Ollama. Load a model there, or
> pick a model.

Each is the desk's own complete sentence and reaches the operator as the guidance
line. **The desk does not load a model to satisfy a pick, and it does not
substitute a different one silently** — moving someone's loaded model is the
operator's decision and not the desk's.

Two cases keep the old behaviour exactly. A server that reports **no** load state
— llama.cpp — is untouched, because there is nothing to check against. An Ollama
Cloud pick is never blocked.

## What a reader sees

Nothing. Every change in this release is on the Editor's Desk's model picker: the
text of the options, which option is first, which one is the default, the help
line beneath it, and the sentence a run stops with. No reader-facing page, feed
or published article changes, and no existing article's model setting is
rewritten — a newsroom that never opens the picker keeps the pick it already had.

## Compatibility

No existing behaviour is removed and nothing changes shape. This release adds
**no migration** and **no new scheduled task, service or program**.

**Use whatever is loaded** is an ordinary row in the model-choice table the
picker already writes — `base_url` and `model_id`, plain text with no value
constraint — so nothing in the database changes shape: no column, table or index
is added, and everything a newsroom has already stored still reads as it did.

The newest migration in the tree remains `0097_suggested_source_origin.sql`,
which shipped with 0.6.70; nothing newer was added here. There is no new
background job, service, installer step or port.

are the authorities for those values; GitHub is the authority for publication
