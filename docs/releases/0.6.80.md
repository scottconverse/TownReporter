This release closes nine design-review notes and worker-reported gaps across
the front page, the Opinion and Queue desks, the story workbench, meeting
capture, backups, and publishing itself: the front page's
header and grid now share one measure at wide windows and the Opinion box
always shows the newest opinion piece; an opinion piece can be published from
its own row; the story-page style check now reports why its button is
disabled and never trusts a client-sent finding; a non-owner sees a plain
refusal on the meeting-capture panel instead of endless loading, and a flaky
navigation walk was fixed; every `ensure*Schema` module now warms up once at
boot; hand-named backups and whole folders are now copied offsite and pruned
under a verified, age-gated rule; a new "Edit the lead" dialog lets an editor
change a lead's title, notes, section or source links; and publishing a story or an editorial with an empty dek is now refused, with
every reader-facing dek falling back to the body's first sentence so the page
never shows a hole. No production deployment or live-model run is asserted by
this note.

## Front page

- **The masthead and the nav rule now share the page's own measure.** From
  1500px wide up, the header bleeds the same `--px` gutter as the rest of the
  page instead of stopping 200px inside it; nothing changes at 1440px or
  390px (`reports/BZ-front-page-notes.md`, `src/reader-astra.css:1980-2000`).
- **"OPINION" no longer prints twice** in an opinion headline; the display
  helper strips the stored `OPINION:` prefix everywhere the front page shows
  a headline (`reports/BZ-front-page-notes.md`, `src/lib/news/editorial.ts:235`).
- **A "This week" row now names the day its own clause is about**, instead of
  a headline that can point a reader to the wrong day
  (`reports/BZ-front-page-notes.md`, `src/lib/story-dates.ts:481`).
- **The Opinion box always shows the newest opinion piece.** Opinion pieces
  no longer appear in the lead or the ruled grid, so the box is never made to
  skip the newest one to avoid repeating it; Latest stories still lists
  opinion (`reports/BZ-front-page-notes.md`, `src/lib/news/reader-articles.ts:33`,
  `src/routes/index.tsx:103`).

## Opinion desk

- **A finished, unpublished opinion piece can be published from its own row**,
  calling the same `publish` mutation and argument the panel's own button
  uses; a piece with a killed run, no draft, an error, or an incomplete
  claims appendix still draws no Publish control
  (`reports/CA-desk-opinion-paste.md`, `src/routes/desk.opinion.tsx:574-585`).
- **The post-save duplicate warning now names the match and says what to do**
  ("Kill one if they are the same") instead of asking a decision the operator
  cannot make after the story is already saved; the pre-save warning, which
  still offers a real choice, is unchanged. The wording was fixed in all
  three places it lived (`reports/CA-desk-opinion-paste.md`,
  `src/lib/news/import-review.ts:324`).

## Story workbench

- **The style check's fix button now says why it is disabled** when it is,
  and a "to read, not to fix" finding can now be ticked and sent for
  repair — a case the button previously discarded silently. The page sends
  only finding ids; the server re-audits the same text and refuses any id it
  did not itself produce (`reports/CB-workbench-fix-style.md`,
  `src/lib/news/draft-audit.server.ts:174`, `src/routes/desk.story.$leadId.tsx:1336`).
- **"Edit the lead" is back on the row's More menu**, opening a dialog to
  change a lead's title, notes, section, or source links; it refuses a
  killed or published lead with a plain sentence and records who changed the
  lead and when on the row itself. The edit also reaches the lead's story
  draft while that draft is still the untouched copy made at filing; a draft
  someone has already worked on keeps its own words, and the dialog says so (`reports/CC-edit-the-lead.md`,
  `src/lib/news/lead-edit.server.ts:38`).

## Meeting capture and operations

- **A non-owner opening meeting-capture settings now sees the server's own
  refusal immediately**, instead of several seconds of loading followed by a
  generic message; the query no longer retries a refusal that cannot succeed
  (`reports/CD-ops-ci-meeting.md`, `src/lib/news/meeting-settings.ts`,
  `src/components/meeting-capture-settings.tsx`).
- **The legal-removal navigation walk's rare CI flake is fixed**: the walk
  now waits for the removed story's title, body, and `robots` meta to all
  settle before reading them, closing a one-tick race with the router's own
  head-content commit; 5/5 local runs passed after the fix
  (`reports/CD-ops-ci-meeting.md`, `scripts/legal-gone-nav-e2e.mjs:274`).
- **Meeting-capture caption and audio capture now retries YouTube's bot
  challenge** with alternate player clients (`android_vr`, `visionos`,
  `tv_embedded` in order), stopping at the first success and recording which
  client won; a failure that is not a bot challenge is not retried
  (`reports/CD-ops-ci-meeting.md`, `src/lib/news/meeting-capture-ytdlp.ts`).

- **All 30 `ensure*Schema` modules now run once at server boot**, instead of
  on the first request that needs each one. The built server holds requests
  until the warm-up is done (Nitro does not wait for plugins before it opens
  the port), and each module logs one `[schema-warmup] <name> <ms>ms <status>`
  line. `legal-removal-schema.ts` keeps its own all-or-nothing path, as the
  file explains (`reports/CE-schema-warmup.md`).

## Migrations

The one migration is additive; it removes or renames no column, table, or
index, and an install with no data affected keeps working unchanged.

- **`migrations/0105_lead_edit_record.sql`** adds two nullable columns to
  `leads` — `edited_at` and `edited_by` — recording who last changed a
  lead's title, notes, or section through the new "Edit the lead" dialog, and
  when. Both are null for every row written before this release, or for a
  lead nobody has edited since.

## Operator notes

1. **A new optional `.env` setting, `TOWNREPORTER_PYTHON`,** names the exact
   Python interpreter meeting capture's yt-dlp calls should run. Left unset,
   behavior is unchanged (today's PATH-order `"python"`); set to a path with
   no file behind it, the tool refuses in words rather than trying a
   different interpreter. The Control page's "Meeting video tools" row probes
   the same interpreter and reports its yt-dlp and ffmpeg versions
   (`reports/CI-python-path.md`, `src/lib/news/media-tool-process.server.ts:40`,
   `docs/setup.md:690`).
2. **The backup tool now also copies hand-named backup files and whole
   backup folders offsite to D:**, verified by file count, total bytes, and a
   per-file SHA256, using the same `.partial`-then-verify-then-rename
   discipline as the dated series. A one-off item is pruned from C: only
   after it verifies against its copy on D: **and** is 14 or more days old;
   an item that looks mid-write is skipped and picked up on a later run;
   nothing is ever deleted from D: (`reports/CH-backup-one-offs.md`,
   `ops/lib-backup.ps1:1181`).
3. **Publishing now refuses a story or an editorial with an empty dek**,
   with a plain sentence asking for one before print. Every reader-facing
   spot that prints a dek — the front-page lead, the Opinion box, the
   story-listing row, and the story page — now falls back to the body's
   first sentence when the dek is empty, so a story published before this
   gate existed shows no visible hole
   (`reports/CK-empty-dek.md`, `src/lib/news/desk.ts:3557-3566`,
   `src/lib/news/dek-fallback.ts`).

## What was not run

- **`reports/BZ-front-page-notes.md`** — `scripts/sources-reach-the-reader.mjs`
  was read but not run: it never opens the front page (its `goto`s are
  `/login`, `/desk/queue#file-lead`, and a published article), so it could
  not exercise this unit's change, and its CI job binds port 8080, which the
  unit could not touch.
- **`reports/CB-workbench-fix-style.md`** — the CI job `desk-production-regression`
  ("The production-desk regression, signed in") was left alone: it needs a
  disposable Postgres service and a mutating setup step, and does not walk
  the story page this unit changed.
- **The first-owner setup code and recovery codes (unit CJ) were taken out
  of this release.** CI showed that 16 browser walks could not create the
  first account, and a code review found three problems: a mistyped setup
  code strands the new owner, a failed audit write during a recovery-code
  reset can lock the owner out, and the recovery-code hashes are fast enough
  to crack offline from a database copy. They return in a later release,
  fixed.
- **The full suite on the merged release branch** ran after every unit was
  merged: the scripts group passed 581 of 583 tests (2 skipped, 0 failed).
  The src group failed one test, `legacy manual drafts still inherit their lead
  citations at publication`, because its hand-written draft had no dek and the
  new gate refused it; the test's draft now carries a dek, and the file passes
  9 of 9. Postgres-integration and live-model tests skip unless opted in, as
  before.
