# TownReporter 0.6.52

**Date:** 2026-09-18  
**State:** Released.

This is the documentation record for the published v0.6.52 source release. It records the GitHub release and Windows package separately from production deployment and live editorial acceptance.

## What changed

### Bounded document-extraction retry

A 37-page document regression exposed that a failed later extraction batch could discard completed earlier work, forcing the next attempt to restart at page one. Extraction now checkpoints pages individually through `extraction_pages` (migration 0063), so a retry resumes at the first unread page and does not reread completed pages. A failed or oversized page remains explicitly unread rather than being folded into a silent success.

### `/desk` boundary repair and CI guard

The reported `/desk` defect was reproduced in the browser walk: a client-side navigation changed the URL to `/desk` while the public homepage remained mounted. The public-home hero entry was repaired in commit `46e706b` by making it a document navigation, and PR #67 extended the same boundary rule to the public footer “Editor’s desk” link, the signed-in masthead “Desk” button, and the error-page “Editor desk” link. Internal desk-router links are unchanged.

The existing `desk-flows` browser job now guards all four boundary entries: public-home hero, public footer, signed-in masthead, and error page. Each assertion requires a fresh `/desk` document load, the editor-desk landmark, and absence of the public hero. The walk also ignores only the expected 404 produced by the deliberate nonexistent error-page route.

PR #66 carries the original route guard and provider-login work. PR #67 carries the remaining boundary-link repair and browser assertions. The audited heads are `46e706b` for PR #66 and `310bee7` for PR #67; both were merged to `main`.

### Provider-login immutable audit history

Failed `provider_logins` rows are now immutable audit history. A successful signed-in probe creates a distinct `done` resolution row linked through nullable `supersedes_login_id`, with a partial unique index allowing at most one resolution per failed row. The insert is transactional and concurrency-safe: it re-verifies the referenced row is the same newsroom and provider and still failed, returns an existing resolution if the state changed, and handles the unique-index race by re-reading and returning the existing row. Resolution detail is meaningful and non-empty.

`providerStatuses` passes its already-fresh `signedIn` decision into the supersession path and no longer spawns a second provider probe per status read. Migration `0064_provider_login_supersession.sql` adds the self-reference and unique index, and the focused provider-login suite covers immutable failed rows, one resolution, meaningful detail, idempotent status reads, and the existing CLI lifecycle.

### Ollama cloud labeling

Hosted Ollama models are labeled as cloud-hosted regardless of documented naming shape. The detector recognizes `:cloud`, `-cloud`, and versioned forms such as `x.y-cloud`, fixing mislabeling in the model picker and reconciliation ledger.

### Lint gate repair and release hygiene

The docs-route test used a NUL control character as a sentinel and failed the repository's `no-control-regex` lint rule. The sentinel is now a private-use character, preserving route normalization while making the full lint command clean. The hotfix reconciliation ledger records the route, provider-login, model-labeling, and release-record work together with its limits.
