# TownReporter 0.6.50

Release date: 2026-09-16. [GitHub release](https://github.com/scottconverse/TownReporter/releases/tag/v0.6.50) · [Windows installation](../windows-install.md) · [Reader guide](../reader.md) · [Editor desk](../editor-desk.md).

This corrective release makes Story drafting work reliably with Ollama Cloud models discovered through the Ollama service running on the TownReporter computer. The service at `127.0.0.1:11434` is the authenticated router; a selected model whose ID ends in `:cloud` performs inference in Ollama Cloud.

TownReporter now reads Ollama's reported model capabilities and context window. The tested `deepseek-v4.1-flash:cloud` route reports a 1,048,576-token context window with thinking, tools and vision. The model picker identifies it as **Ollama Cloud · 1M context · thinking off · vision** and explains that inference is hosted.

DeepSeek V4 is now recognized as a reasoning model. For drafting, TownReporter sends `reasoning_effort: none` by default so hidden reasoning cannot consume the complete 2,200-token output allowance before the model writes the Story response. The context window remains available for large input packets. An operator's explicit `LLM_REASONING_EFFORT` value still takes precedence.

## Verification

The production failure was reproduced from its durable job record: the selected `deepseek-v4.1-flash:cloud` job reached **Writing the draft** and returned reasoning without final Story content. The corrected code completed a live five-stage `reportAndDraft` run through the same Ollama Cloud model in 10.7 seconds, producing a source-linked draft after research planning, writing, evidence reconciliation and name checking. No article was published by this test.

A separate review agent queried the live Ollama metadata and confirmed `deepseek_v41.context_length = 1048576`, thinking and vision capabilities, and a normal final response when TownReporter sends `reasoning_effort: none`. The 44 focused reasoning, discovery and picker tests passed, as did TypeScript checking and the diff check. GitHub CI and the packaged Windows installation gate the tag; production promotion is recorded separately after merge.
