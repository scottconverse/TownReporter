## Redesign phase 2a: the desk shell, Today and the Queue (PR #122)

The desk's left nav is now the drawn order — **Today, Queue, Drafts,
Published, Opinion, Follow-ups, Dark Desk, Sources & scan, Models, Server,
Stats** — with a count where a count means something, and the footer's
**View the paper ↗**, light/dark switch, text-size select and keyboard-shortcut
hint live in every screen because there is one shared nav. On a phone the nav
collapses to a top bar with the wordmark, a **Desk** tag, **+ New** and
**Menu**, and that phone bar keeps its pinning across the desk instead of
scrolling away.

**Today** (`/desk`) opens on the drawn four-step strip — **Pick leads / Draft
/ Check / Publish** — each cell a number, a name, a count and one button, with
**Running now**, **Tonight's edition**, the start-a-draft composer, import,
paste, and **New leads** underneath.

The **Queue** keeps its **Open / Held / Killed / ≈ Printed / All** segments,
search, sort and section, with the bulk strip moved to its own row below the
filters so selecting rows no longer reflows the controls above them. Two new
dialogs come off the Queue: one for **drafting the selected leads** (batch
draft, with the desk's model and effort picker) and one for **filing a lead
yourself**, reachable from **+ Add a lead** and no longer landing on a shut
form when opened by its hash link.

**The batch panel's Dismiss button is now the plain outlined style.** Filing
this under phase 2a because that is where it landed: an audit of the batch
panel (finding BS-001) found **Dismiss** drawn as the yellow primary action,
reading louder than the "Redraft with …" presses that are the actual work on
that screen, so it now carries the quiet, 1px-outlined style already used for
the dialog's own Cancel — same button, same behavior, quieter paint.

One defect this phase found and fixed on the way: a lead filed by hand got a
draft row with an empty body, so it fell through to the last branch of the
draft-state rule and announced **"Ready to check"** — while the nav's Drafts
count, which counts leads whose status is `drafted`, said 0. There is now a
fact for it (`has_body`) and its own state, **"Nothing written yet,"** with
**Start story** as its one action.

## Redesign phase 2b: the story workbench (PR #124)

The story workbench (`src/routes/desk.story.$leadId.tsx`) is redrawn in one
column, in the drawing's order: a top bar (**← Today**), the lead's context
row on its own line, a 4-step stepper — **Lead / Draft / Check / Publish** —
derived from what the page already knows rather than stored, then the action
row and the `420px | 1fr` split with the Checks/Sources/Reporting tabs on the
left and the writing surface on the right.

**Redraft** now opens a dialog that asks what should change (the lead's story
direction) rather than redrafting on one press, and it keeps the editor's own
headline by default — the model's line is used only when the headline was
never edited by hand (`headline_source` is not `"editor"`). Same two calls
underneath, in the same order, as the button it replaces: `saveReportingNotes`
then `draftLead`.

A **Preview dialog** shows the story as it will print before publish. The
sticky **publish bar** lists **Saved**, **Evidence checked**, **Names
reviewed** and **Preview viewed**, each ticked or flagged from the same
derived state the stepper uses, and carries the inline confirm — **"Yes, print
it in `<section>`"** or **Not yet** — in the same press that already commits
the section, same as every release since 0.6.67.

The **legal-removal dialog** is drawn as the design here too, alongside the
same set of story dialogs (Kill, Compare versions and the rest) phase 2b
built out.

## Legal removal on in-app navigation (commits e6bca61f, 01a957eb)

A story removed for legal reasons already answered HTTP 410 at its own URL
with a plain "This story was removed." page. A reader who reached the same
slug by a link inside the paper, or by pressing **Back** to a story that was
live when they opened it, instead got the router's ordinary "not in this
edition" panel — and, because a loader that throws leaves the previous
match's `loaderData` in place, that panel still carried the removed story's
own share-card head (`og:title`, `og:description`, `article:*`, `twitter:*`)
and page title.

The route's loader now succeeds with `{article: null, dates: null,
legalGone: true}` on that path instead of throwing, which replaces the
previous match's data wholesale: the panel, the head and the document title
all say the removal, with `robots: noindex` and none of the removed story's
headline, dek or body. The full-page-load 410 path is unchanged. The
removal's heading and sentence are shared exports so both doors print the
same words, and a test asserts the 410 page and the in-app panel agree.

**New CI job, `legal-gone-nav`** ("A legally removed story says so on in-app
navigation, in a browser"): boots its own copy of the built server on port
3523 over in-memory PGlite, seeds one story to remove and one to leave up,
walks front page → the story's own link → breadcrumb back → removal through
the desk's own `previewLegalRemoval`/`removeLegally` → **Back**, and asserts a
navigation sentinel survived so the 410 page cannot arrive on its own and
satisfy the checks.

## What a reader sees

Everything in phases 2a and 2b is on the signed-in editor desk. The legal-
removal fix is the one change reachable from the public paper: a reader who
navigates in-app to a removed story, rather than loading its URL directly,
now sees the same removal notice and leaks none of the removed story's
content into the page's head.

## Compatibility

No existing action is removed on the desk; the redesign phases restyle and
relayout screens that keep every action they had, following the same drawings
named in `docs/design/handoff-2026-09-26/`. Nothing changes shape at the data
layer: no migration, no new column, no new route.

## Limits

The redesign phases' own evidence is what each unit measured against a
throwaway in-memory desk or PGlite instance, in a browser, at a small set of
widths and both appearances — not a full walk of every desk screen at every
width. The legal-gone-nav walk covers the one in-app path (front page, link,
breadcrumb, Back); it does not cover every possible route a reader could use
to reach a removed slug.
