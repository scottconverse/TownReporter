This release is **the desk's five main screens restyled to the redesign

to notes.** Phase 2c of the redesign reaches Opinion, Sources & scan,

2026-09-26: the paper no longer waits behind a nightly `pg_dump`, the
watchdog recognizes its own server on Windows, and a failed backup logs how
far it got before it is deleted rather than being kept unread. And the
Reporting tab's claims and sources gain a short, readable site link, a
**Pull** that reads the exact source page, and an **Add to notes** that keeps
the claim as a reporting lead — alongside a fix so an editor's own reporting
notes finally reach **Redraft** on an ordinary story. **No model was called
and no model was loaded** to build or check this release outside the one

## The paper no longer waits for a backup

On 2026-09-26 an editor opened the leads page while the nightly `pg_dump` was
running, and the page did not load until the dump finished. Nothing was
broken — the two were queueing. Almost every page's first database call
brought the paper's own tables up to date before doing its real work,
statement by statement, on **every** call. `create table if not exists`
against a table that already exists is cheap, but `alter table ... add column
if not exists` takes the strongest lock there is, and `pg_dump` holds a read
lock on the table for as long as it runs — so the ALTER queued behind the
dump, and every other read of that table queued behind the ALTER.

The paper now records, per batch of statements and per database, that the
batch has already run — in a small table it owns (`_schema_ensure_state`) —
and skips the batch from then on. The first call in a process still does the
work; every call after it is two round trips and no DDL at all. Sixteen
modules were still running their statements on every call; they now go
through one helper, `ensureSchemaOnce` (`src/lib/db.ts`), twenty batches
between them. The ten modules already routed through it are unchanged, no
statement's text was reworded, and no statement's order changed. One of the
sixteen is the paper's settings, which the public front page and the feed ask
for on every load, and another is the beacon that counts a page view — so
this is the public's path too, not only the desk's.

`src/lib/news/paper-settings-read-lock.test.ts` opens a second connection and
holds the same read lock `pg_dump` holds on `paper_settings`, warms the read
path once, then calls the public read again: it did not return inside two
seconds before this change, and returns at once after it. It needs a real
Postgres and runs in the postgres-integration set rather than the ordinary
suite. `src/lib/news/schema-ensure-second-call.test.ts` counts the statements
a second call actually sends — exactly two, the marker table's own create and
the lookup that decides to return early — against the in-memory database the
test process already builds. `legal-removal-schema.ts` is left alone on
purpose: it has its own transactional marker and `assertLegalReady`, which is
strictly stronger.

## The watchdog knows its own server

On the same night the watchdog found the stalled server holding port 3000 and
logged *"which is not this app -- not touching it"*, so the paper was never
restarted. It compared a path written with forward slashes against a command
line Windows reports with backslashes, and that comparison cannot match — so
every port owner took the "not this app" branch. The watchdog now asks the
same shared predicate `Test-TownReporterServerProcess` (`ops/lib-port.ps1`)
uses elsewhere, which normalizes the slashes first and still refuses a second
installation or an unrelated `node.exe`. Both predicates are run in a real
PowerShell process by the tests, under backslash, forward-slash and mixed
spellings.

## A backup that fails cleans up after itself

A dump that died part way — the database went away, the disk filled, the
machine was restarted — used to leave its half-written file in the folder,
renamed `.incomplete`, with the newest two kept "for inspection." Nobody read
them. A paper whose database is down at 2 AM asks for a backup every five
minutes, so 300 MB of half-written dump could land 288 times in one night,
and the system disk is the one that fills.

`Remove-TownReporterFailedDump` (renamed from `Move-...`) now writes one plain
log line first — the file's path, the byte count `pg_dump` had reached, and
the last 2 KB of the file as text with control characters stripped — so an
operator can still see how far it got. Then the file goes. It also sweeps any
`*.sql.incomplete` left by the older version out of the folder a dump was
just attempted in: only that pattern, only that folder, so a real backup or a
hand-named safety copy is still never deleted.

`scripts/ci-backup.ps1` proves it against the real library with a fake dump
command and no database: a run whose dump works deletes nothing (a planted
leftover survives it), a run whose dump is cut short deletes its own file and
the older leftover, no `.incomplete` remains, and the log carries the exact
number of bytes written and the tail it read.

## Every sourced claim gets a readable link, Pull and Add to notes

The Reporting tab's **Claims and sources** list printed a bare URL under each
claim, with no way to read the claim's own source or keep it as a reporting
lead. Each claim's source link now shows the short site name — `example.com`,
`www.` stripped — as the link text, with the full address in the link's
`title` (so it shows on hover) and its `href`, instead of a URL that used to
wrap into a column of fragments in the inspector's width.

Two buttons sit beside each claim:

- **Pull** reads that exact source page through the existing ingest guard —
  the same safety checks as any other Pull, and **no new model call** — and
  drops the excerpt in the box under the story. The receipt carries the
  claim's `sourceUrl` and skips the search-shaped path an ordinary reporting
  Pull takes.
- **Add to notes** writes one line, `<claim> — <url>`, through the existing
  reporting-notes add path. It is disabled while saving, and a line already
  present is not written twice.

`scripts/claim-sources-pull-walk.mjs` proves the whole path end to end on a
seeded story against a fake provider, and CI runs it in its own job,
**`claim-sources-pull-0674`**. The walk's control uses literals specific to
the fake channel that the model cannot echo from its own draft, so a hit is
real evidence rather than a coincidence of wording.

## Redraft now reads the editor's own reporting notes

Before this release, lines an editor added to a story's reporting notes never
reached **Redraft** for an ordinary, non-meeting story — only a meeting
story's material carried them forward. The desk's patch now passes
`editorNoteLines(prevNotes)` as `editorNotes` for the no-meeting-material
case too, so the editor's own lines reach both prompts Redraft can take. They
arrive labeled as **leads to verify**, not as evidence the model may cite as
already confirmed. `src/lib/news/report.editor-notes.test.ts` proves it.

Nothing on the public paper changed. Every change in this release is on the

## Migrations

**None.** `git diff 5629cc79..HEAD --stat -- migrations` (`5629cc79` is the
0.6.73 release merge) shows no files under `migrations/` changed since the
last release; the ledger stays at `0103_read_hourly.sql`.

## Compatibility

No existing behavior is removed and nothing changes shape. The schema-ensure
change is a caching layer in front of statements that already ran on every
call; the statements themselves, their order and their text are unchanged.
The backup change only touches what happens to a file that was already going
to be deleted as incomplete. The claim-sources change adds two buttons and a
link's display text to an existing list; no stored shape changes, because the
reporting note the Add-to-notes button writes uses the same free-text row the
notes panel has always accepted.

## Limits

**The schema-lock test needs a real PostgreSQL** and runs in the
postgres-integration set; on a machine without one it is not exercised.
**The watchdog fix was proven against constructed command lines**, not a
second live installation caught in the act. **The backup fix was proven
against a fake `pg_dump` and no live database** — a real out-of-disk failure
on a running paper was not reproduced to check it. **Pull's browser walk runs
against one seeded story and one fake provider**; it is not a live-provider
proof, and no model was called or loaded anywhere in this release's checks.
**The phase 2c evidence was taken on an empty desk** — no editorials,
published stories, scans or open Dark Desk file — so what is proven is the
shape of every screen at 1280 in light and dark and at 390 in light, not its
appearance with real newsroom data. **`/desk/dark` still has no honest light
build**: the route passes the night flag as before, so its light and dark
captures are the same page, which is the desk's own rule and not a change
here.
