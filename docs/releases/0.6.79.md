## The picked Queue row carries the drawing's panel fill

The design drawing builds the Queue row's whole style and appends
`background:var(--panel)` only when the row is selected
(`docs/design/handoff-2026-09-26/design/Desk Screens.dc.html:284`). In the
drawing, then, the list reads as bare paper with rules, and the one picked row
is its only `--panel` block. The desk drew no picked state at all: the tick in
the first column was the row's only sign it was in the bulk bar's set.

`LeadRowView` now puts `picked` on the row's `.lead-row` when that row's own
selection box is ticked — the same `deleteSelected` state the box itself
renders from — and `.desk-ltr.astra .lead-list.roomy .lead-row.picked` carries
the fill.

**The color is not a one-line addition, because `--panel` and the row's own
fill are the same color here.** The desk paints every `.lead-row`
`background: var(--surface)`, and `--surface` **is** the prototype's `--panel`
in this app: the shell's own mapping (the phase-2a token block in
`src/desk-astra.css`) is `--panel->--surface`, and the values match on both
sides — `#f6f2e7` in light, `#27231f` in dark. Painting `.picked` with
`--panel` alone would therefore have changed nothing on screen. What buys the
tint is stepping the **unpicked** Queue row back to the page (`var(--bg)`),
which is what the drawing's rows already are, since they carry no fill of their
own; the picked row keeps the `--panel` block.

The change is scoped to `.lead-list.roomy`, the Queue's own table, so
Published, Scan, Drafts and Dark Desk rows keep the fill they had. The killed
row keeps working: `.dead` is `opacity`, which multiplies whatever fill is
underneath it. The row's existing `padding: 10px 24px` already holds text off
the edge, so no side padding was added and **no unpicked row moved** — the tint
is a fill, not a press, and changes no box.

**Contrast.** Measured with computed colors on a built server, not read from
the sheet, in both themes: the picked row's fill is `rgb(246,242,231)` light
and `rgb(39,35,31)` dark, against the page's `rgb(255,253,247)` and
`rgb(27,25,22)`. Every text color on a picked row passes WCAG AA in both
themes — the weakest on the panel is the muted ink at **10.17:1 light** and
**8.05:1 dark**, body ink is 16.88:1 and 12.5:1, and control text drawn on its
own fill is **9.05:1** at the weakest (the model chip in dark; 11.18:1 in
light). Nothing under 14px was added.

**The check.** `scripts/lead-badge-render.test.mjs` renders the real
`LeadRowView` both ways and asserts that a ticked row carries the class and an
unticked row does not (and that a killed row can carry both states), then
asserts that the rule the sheet tints with still uses the prototype's `--panel`
and that the `--panel->--surface` mapping is still in the sheet. It is the same
SSR-of-the-real-component style the rest of that file uses.
`scripts/by-queue-tint-shots.mjs` is the browser walk that filed its own leads
on a built server, ticked a row, took the computed numbers above and captured
the light and dark screenshots.

**No migration.** `git diff origin/main...HEAD --stat -- migrations` shows no
output — nothing under `migrations/` changed since the 0.6.78 merge base
(`0ee9af05`, which is this branch's base and `origin/main`).
